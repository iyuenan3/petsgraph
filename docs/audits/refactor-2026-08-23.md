## 人工验收门禁

### macOS

启动开发 App 前先备份现有 `~/Library/Application Support/PetsGraph/` 和相关 UserDefaults，因为开发版沿用正式应用身份并会写入新数据根。之后必须人工完成：

1. 零宠物启动，只保留状态栏入口。
2. 依次装载五百和飞流，确认菜单名称来自包，不写死。
3. 正常速度同时观看，确认独立时钟、无卡帧、无闪动、无硬切、无窗口位移。
4. 分别与全部执行显示、隐藏、卸载，确认隐藏跨重启保持，卸载只删除内部副本。
5. 拖动两只宠物并重启，确认位置保持；逐档检查 `0.5` 至 `2.0` 全局大小。
6. 检查透明区域点击穿透、宠物不响应点击动作、会议投屏隐藏语义和长时间内存表现。
7. 由用户明确记录正常速度视觉结论，未明确通过前不得批准候选包。

### Windows x64

## 远端验证

首次推送把远端 `main` 从 `cd11a52f8229a8366029ef0210a08fba17cc60e2` 前进到 `a7c2cb594734fa4e337056ac74eeca18ded0825a`。macOS 工作流通过，另外两条工作流发现了两个不同的测试输入问题：

1. PetPack contract 的 Windows job 发现 Python `ZipInfo.filename` 会在 Windows 上先把反斜线改成正斜线，原测试没有实际写入恶意原始路径。`1937a03` 改用 `orig_filename` 校验并固定测试归档原始条目名。
