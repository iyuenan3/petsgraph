# CONVENTIONS：petsgraph

## 命名

- 项目、包和文件路径使用小写英文 kebab-case。
- 图节点使用层级点号，并显式保留场景语义：`rest.prone.left`、`sit.front.floor`、`sit.front.cat-bed`、`gateway.pillow.b`。
- 片段 ID 使用 `<action>-<direction>-<role>-v<n>`，例如 `walk-right-loop-v1`。
- 方向始终写完整单词 `left`、`right`、`front`，不使用 `l`、`r` 等缩写。
- 帧文件使用从 `0000` 开始的固定宽度序号。
- 已批准素材不可原位覆盖。修订版增加版本号并保留旧版本与拒绝记录。
- 面向用户的节点必须提供简洁中文 `displayName`。节点 ID、clip ID 和边 ID 只属于内部契约，不能出现在正式菜单、状态栏或普通错误提示中。
- App 品牌固定使用 `PetsGraph`，Bundle ID 使用 `com.maxwell.petsgraph`。宠物包使用自己的 ID 和 `pet.displayName`，通用 Swift 代码、DMG 模板和菜单不得写死李五百或未来任何具体宠物名。

## 偏好模式

- 把“生成母片”“制作事实源”“运行时编译物”“预览文件”放在不同目录和状态中。
- 一个生产单元一次只解决一个动作、一条有向边或一条可以确定性拆分的连续路径。允许从连续母片切出 transition、loop 和独立 return，但每段仍分别验收。
- 每次 provider 调用记录输入哈希、模型、参数、任务 ID、开始时间、结果状态和尝试序号。
- 每个用户通过的动作或图边立即固化独立 `approved-recipe.json`，每只宠物用 `approved-assets.json` 汇总，不把生成方法只留在聊天、命令历史或临时日志中。
- 新编译配置必须固定 `approvedRecipeSha256`。编译器在复制帧前校验配方身份、批准状态、事实源路径、帧数、FPS 和有序序列摘要，不把仅凭路径同名的文件视为已批准输入。
- 从本规则生效后，缺少完整生产履历、确定性处理脚本哈希或人工批准证据的素材，不得进入 `human-action-approved` 或 `human-edge-approved`。
- 网络结果未知时记录为 `unknown`，先查询任务账本，不自动重投。
- 每次重试必须写明相对上一版改变了什么失败假设、动作分解、端点、画布、提示约束或模型策略。核心素材在用户明确授权后不受固定尝试次数限制，但禁止只换 seed 重复抽取。
- Seedance 负责正式连续动作视频。Seedream 与 `gpt-image-2` 只用于静态身份基准、姿态锚点、安全画布、outpaint 和严格首尾参考。静态结果进入 Seedance 前和动作生成后都要分别验收。
- 本机 `gpt-image-2` 只通过 `GPT_IMAGE_API_KEY`、`GPT_IMAGE_MODEL`、`GPT_IMAGE_GENERATIONS_URL` 与 `GPT_IMAGE_EDITS_URL` 配置。仓库、AIREADME、任务账本和日志不得记录变量值或完整认证头。
- 不要求不同宠物共享姿势名称、姿势数量、道具或动作图。共享运行时只解释数据契约，宠物差异进入独立包配置和私有批准履历。
- root motion 存累计值；运行时按时间直接采样，不累加 delta。
- 每个片段同时保存逐帧 `rootMotionPt` 和终点 `rootMotionEndPt`，循环换相位时按每帧相邻累计值恢复 delta，再从新入口重新累计。
- 跨姿态切换使用单独有向边；同一稳定姿态上的有限活动可以自环。
- 面向用户的坐姿按视觉场景区分，例如 `sit.front.floor`、`sit.front.pillow` 与 `sit.front.cat-bed`，不按即将移动的方向复制。历史 `sit.front` 兼容到普通场景，不代表可以丢掉场景道具。
- 私有素材契约、评审 manifest 和正式包使用同一节点 ID。猫窝正面坐姿一律写作 `sit.front.cat-bed`，不得另建 `rest.cat-bed.sit-front` 等同义节点。
- 倒放例外只适用于同一节点的低频偶发自环，并且必须人工验收完整正放加倒放结果、显式记录帧范围且保持不可中断。不同节点或场景之间的任何回程仍必须独立生成和验收。
- 节点必须声明 `scene`、`role` 和 `autonomousEligible`。`gateway` 与 `interaction` 不能进入自主随机候选集。
- 普通睡姿与枕头睡姿是两个场景。枕头只通过批准场景边出现和离开，场景内部节点必须保持道具集合、尺度和方向连续。
- 靠枕 B 固定为 `gateway.pillow.b`，只短暂停留并播放已批准短循环，不作为随机睡姿。
- 睡眠行为使用随机长尾停留、最小停留和近期去重。具体时间属于行为配置和人工验收，不写入 clip 帧时长。
- 随机换姿使用动作图上的加权随机游走。先筛除当前节点、近期两个姿势、冷却活动和非法场景，再选择目标并规划完整路径；串行 QA 预览不能直接成为正式播放顺序。
- 用户指定睡姿和自主换姿复用同一个动作图、预加载和安全退出机制。不可中断过渡期间只保留最后一次有效选择，禁止强行切帧。
- 点击只解析宠物本体，按当前场景请求对应正面坐姿；透明区域和枕头不触发。桌面其他位置点击在 MVP 中忽略。
- 拖动属于强操控，允许改变窗口 x 和 y。用户松手后的 y 成为新基准，普通动作和场景内切换不得改变它。
- 安静陪伴模式首次显示使用物理屏幕左下角，不使用可见工作区中心或 Dock 上方安全区。普通工程预览可以保留自己的启动布局，但不得改变正式模式默认值。
- provider 终端帧是否保留必须逐条边依据端点相似度和目标循环相位决定。履历必须记录保留或排除的帧、边终点相位与下一运行时相位，禁止套用统一删除规则。
- 稳定姿态到步态的 root motion 在第一步明确朝目标方向迈出时开始，并在进入循环前连续接上已批准速度；素材通过与位移曲线通过分别记录。
- 包加载器从动作图引用推导片段清单并显式寻址，不依赖目录枚举顺序或可见结果。
- 运行时预览序列不得绕过动作图：过渡只能从第 0 帧完整播放一次，相邻片段的入口与出口姿态必须一致，循环离开时的最后运行时帧必须属于 `safeExitFrames`。下一条边或目标循环必须在切换前可解析并预加载。
- 同一批准动作路径的画布归一化使用一个固定变换，且只作用于编译副本。禁止逐帧根据 alpha 包围盒重新居中。
- 粗抠对齐一旦经整链人工通过，该 clip 的固定缩放与平移即成为后续精抠输入锁。精抠不得根据新 alpha 包围盒重新缩放或平移，也不得让同一素材在不同闭环中使用不同几何。
- 精抠采用选择性更新。已在深色、浅色和棋盘格背景下干净的 clip 逐字节复用；只重做有明确毛边、背景污染或主体保护问题的 clip。任何自动清理都必须证明耳朵、鬃毛、胡须、四肢、脚掌和尾巴未被挖掉。
- 低功耗 raw 媒体按 clip 计算一次全帧 alpha 并集，再统一增加固定透明边距。该矩形只缩小存储窗口，锚点、碰撞区、root motion 和完整画布坐标全部保持不变。
- 低功耗编译器默认输出 `installable=false` 候选。只有来源 PNG 包已达到 `runtime-chain-approved` 与 `installable=true`，并获得明确版本发布授权时，才允许用显式 `--release-approved` 生成正式语义版本；发布工作流必须再次核对 schema、渲染模式、批准状态和剩余闸门。
- 预乘 RGBA 编译物使用 `rgba8-premultiplied`、`premultiplied-last`、sRGB 和连续帧流。媒体字节数必须严格等于 `frameCount × frameByteCount`，媒体 SHA-256 必须与 clip 元数据和完整性清单一致。
- 运行时只保留当前 clip、下一条边和目标循环。小型循环可预建完整 `CGImage` 集，长过渡按固定 crop 分块预建，禁止用逐帧 PNG 解码或逐帧 `CIImage → CGImage → NSImage` 重建作为长期路径。
- 正式 GUI 运行使用每用户进程锁。重复启动必须在加载数百 MB 媒体前立即退出；命令行 `--validate-only` 与 `--validate-media` 不参与锁竞争。
- 性能测量先用精确命令路径和 PID 清除旧版本。AppTranslocation、Gatekeeper 延迟放行和历史预览包必须单独识别，不能把两个版本的 CPU 与内存合并后归因给当前候选。
- 含道具帧同时记录宠物命中区、道具区域和猫道具联合屏幕边界。不能用联合 alpha 直接判断是否点击了宠物。
- 宠物包临时构建目录不用点号前缀。编译完成后必须检查根目录及全部子项没有 `UF_HIDDEN` 标记，再执行目录级安装。
- 数百 MB 的正式媒体不写入 Git 历史。默认宠物包内嵌在 App 中，不再作为重复 Release 附件。公开发行使用版本化 DMG、备用 App ZIP、总览图、校验和、仓库内固定清单、字节数和 SHA-256；草稿只有在远端测试和精确附件集合校验通过后才能发布。
- DMG 与 App ZIP 在本机从冻结 App 构建。GitHub Actions 只下载、校验并发布草稿，不把远端重新编译的不同二进制冒充本地已验收附件。
- 首个公开版只构建 Apple 芯片 `arm64`，最低 macOS 14。Intel 或通用二进制只有在明确进入新产品范围并重新验证后才能增加。
- 所有正式评审同时查看透明素材、浅底、深底和真实桌面尺寸。
- 首尾帧提交前检查完整宠物包围盒和预期尾巴运动包络。可见主体不得进入画布外圈 8px，尾巴会摆动的动作必须预留额外左右安全边界。
- 输入端点满足安全边界不代表生成结果自动满足。每次生成后必须逐帧测量四侧最小边距和主体中心漂移，并把未达到提示词目标但尚未裁切的偏差交给整链人工验收。
- 步态验收必须以正常速度和必要的慢速视频检查承重脚。接触表只能确认离散姿态，不能证明接地脚没有滑动、瞬移或融形。
- 接触表与预览标签不得覆盖尾巴、脚掌或画布边缘，避免缩略图掩盖裁切缺陷。
- 中文文档不用破折号字符，使用逗号、句号、冒号或括号。

## 禁用模式

- 禁止用随机动作数组、固定定时器和硬切实现行为调度。
- 禁止把 `gateway`、`interaction` 或过渡 clip 放进自主睡姿随机池。
- 禁止在睡眠 MVP 中监听宠物之外的桌面点击，或把点击目的地移动作为默认行为。
- 禁止在同一枕头场景内无过渡添加、删除、缩放或替换枕头。
- 禁止把枕头 alpha 当成宠物点击区域。
- 禁止在动作变化时无条件从目标第 0 帧播放。
- 禁止用固定 `speed` 字段代替逐帧 root motion。
- 禁止用 CSS 或画布内部位移冒充原生桌面窗口移动。
- 禁止默认水平镜像正式宠物素材，除非具体动作记录 `mirrorSafe=true` 且有人工批准。
- 禁止把骨骼、局部肢体拼接、RIFE、光流、交叉淡化或自动补间生成的帧混入正式直接视频帧。
- 禁止抠图失败时静默复制上一帧蒙版。
- 禁止通过整体平移、补画尾尖或不连续裁帧修复已经在生成母片中被画布裁断的肢体与尾巴。
- 禁止把机械检查、自审或预览编码成功写成用户批准。
- 禁止用 `clips/` 目录枚举结果代替动作图引用校验。
- 禁止把 hidden 必需文件当作普通合法包内容，也禁止要求用户手动运行 `chflags` 修复编译器产物。
- 禁止一次批量生成全部动作后再统一验收。
- 禁止把一只宠物的十姿势模板、场景图或随机权重复制为所有宠物的默认方案。
- 禁止把 `gpt-image-2` 或其他静态生成结果直接标记为动作通过、运行时整链通过或可安装。
- 禁止用固定三次上限拒绝继续改进已经确认属于 MVP 核心的素材；也禁止以“额度充足”为理由进行无假设批量抽卡。
- 禁止在仓库、日志、宠物包或 AIREADME 中写 provider 凭据和原始私密照片信息。
- 禁止在生产履历中保存密钥、访问令牌、签名 URL、临时下载地址，或用推测值填补历史缺失字段。
- 禁止把代码的 MIT License 自动扩展到李五百照片和动画素材。媒体使用边界以 `ASSETS.md` 为准。
