# ROADMAP：petsgraph

## Now（李五百睡觉陪伴 MVP）

当前唯一产品焦点是完成一个可长期运行的五百睡觉陪伴版本。走路、跑步和点击目的地移动不再是首发闸门。

1. 冻结普通睡眠子图：从已批准的趴卧、蜷卧、香箱、伸展和仰卧素材中选择首发节点，补齐安全退出、预加载和完整返回路径。
2. 冻结点击链：验证每个首发睡姿能在目标响应时间内进入 `sit.front.floor`，再次点击后返回睡眠。路径过长时只为关键深层睡姿补直接醒来边。
3. 完成枕头场景：分段并验收已通过的母片范围，补靠枕网关短循环、自然下枕回程、`sit.front.pillow` 及其双向过渡。
4. 构建睡眠行为调度：默认睡眠、随机长尾停留、近期去重、枕头场景粘性、网关与交互节点排除、点击目标去抖和安全排队。
5. 收敛窗口交互：只保留宠物本体点击和全桌面拖动，移除首发模式对全局桌面点击监听与点击目的地移动的依赖。
6. 编译新的带版本号睡眠 MVP 包，验证固定画布变换、猫体点击区、猫枕联合屏幕边界、严格零睡眠 root motion 和完整性清单。
7. 完成真实桌面 30 分钟观察、正常速度与慢放关键链验收，只有全部通过后才标记 `runtime-chain-approved` 和 `installable=true`。

## Next

2. 验证锁屏、系统睡眠、多 Space、全屏应用、Dock 前方层级和重新启动后的稳定恢复。
3. 记录五百首发包全部批准素材的可复用生产方法，并把照片输入、provider 调用、抠图、QA、人工暂停和包编译抽象成素材生成 Skill。
4. 使用第二只高辨识度宠物验证 Skill 是否摆脱了五百专属手工知识。
5. 根据长期观察决定是否加入低频伸懒腰、舔毛或轻微注视。任何新增动作都必须服务陪伴感，不能为了展示能力而加入。

## 已搁置（+原因）

- 点击桌面目的地后走路或跑步：与首个产品价值无关，并引入全局点击监听、方向、边界和响应状态复杂度。
- 自主巡游：会持续抢夺注意力，破坏安静陪伴。
- 玩耍、进食、复杂互动和命令面板：没有证明比高质量睡眠更能提高留存陪伴感。
- 多宠互动：关系、碰撞、遮挡和素材规模会同时扩大，偏离单宠质量主线。
- 云账号、同步、市场和付费代生成：用户自行配置 provider，项目不承接额度和私密素材托管。
- 骨骼、肢体拼接、Hatch Pet、RIFE、光流和自动补间作为主路线：机械连续不等于真实宠物动作自然。
- 动态 WebP 作为唯一运行时格式：不能保证精确逐帧寻址、安全退出、点击区域和 root motion 同步。
