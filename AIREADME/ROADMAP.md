# ROADMAP：petsgraph

## Now（macOS v0.5.10 观察与 Windows v0.6.0 内部验收）

PetsGraph v0.5.10 已完成双宠运行时、真实桌面验收和 Apple 芯片 DMG 发布。五百与飞流两个 `0.5.10` 包均为 `runtime-chain-approved` 和 `installable=true`，合计 84 个 clip 与 12,013 帧。当前焦点从“能否发布”转为“朋友长期使用是否稳定且安静”。

Windows `v0.6.0` 已有一份只面向 Windows 11 x64 的 .NET 10 WPF 实现和本地双宠便携 ZIP。本机交叉编译、真实包完整性、x64 PE/ZIP 检查和 GitHub Windows Runner 均已通过，但还没有在真实 Windows 11 桌面完成 GUI 人工验收。

1. 收集朋友在 Apple 芯片、macOS 14 及以上环境的下载、首次打开和长期陪伴反馈。
2. 分别观察单宠与双宠整日运行的 CPU、physical footprint、`ps` RSS、换姿峰值和锁屏恢复，保留测量工具与唯一 PID 口径。
3. 记录菜单装载、指定睡姿、七档缩放、拖动持久化、猫窝路径和透明边缘的真实回归，只修复有明确复现证据的问题。
4. 冻结五百与飞流已批准素材和相对位置关系。飞流保持 `baseHeightPt=181.125`，五百保持 `172.5`，不因主观微调修改媒体帧。
5. 保持 v0.4.0 与既有制作事实源可回滚，不删除历史标签、批准包或生成履历。
6. 在至少一台真实 Windows 11 x64 机器上验收解压、首次启动、未签名安全提示、托盘、显示隐藏、退出和重复启动单实例。
7. 使用 100%、125%、150% 等系统缩放检查透明区鼠标穿透、宠物本体点击、拖动位移、七档缩放和持久化恢复。
8. 按五百地面与枕头往返、飞流地面与猫窝往返、双宠独立随机和边界位移做正常速度人工观察。
9. 完成至少 60 分钟 Windows 双宠运行，记录崩溃、窗口消失、无限过渡、请求堆积、锁屏恢复、CPU 和内存。

## Next

1. 申请 Developer ID、完成 Apple 公证并优化首次安装体验。在此之前持续清楚展示 ad-hoc 签名和手动确认边界。
2. 后续版本继续只发布一个 Apple 芯片 DMG，不恢复 App ZIP、预览图、校验和附件或独立宠物包。历史 Release 保持不变。
3. 把 provider 调用、任务账本、抠图、QA、批准履历和包编译整理为内部可复用工具，但保留每只宠物的人工姿态设计、图设计和验收。
4. 根据飞流真实使用决定是否增加低频耳动、砸吧嘴、伸懒腰或其他符合它习惯的小动作。
5. 只有在猫窝首版稳定后，才重新设计符合猫窝接触关系的踩奶活动。历史毛毯踩奶不直接迁移。
6. 依据真实需求决定是否支持登录时启动。
7. Windows 11 真机闸门通过并获得明确分发授权后，再决定是否把本地 ZIP 上传到草稿 Release。内部朋友使用不要求代码签名或 MSIX。

## 已搁置（+原因）

- 点击桌面目的地后走路或跑步：与首个产品价值无关，并引入全局点击监听、方向、边界和响应状态复杂度。
- 自主巡游：会持续抢夺注意力，破坏安静陪伴。
- 玩耍、进食、复杂互动和命令面板：没有证明比高质量睡眠更能提高留存陪伴感。
- 多宠互动：当前只支持多个独立宠物窗口。关系、碰撞、自动避让和跨宠动作会同时扩大素材与状态空间，继续搁置。
- Intel Mac 与通用二进制：首批朋友的目标设备是 Apple 芯片，先减少发布矩阵和未验证环境。
- Windows 代码签名、MSIX 与安装器：当前只在明确知情的内部朋友之间分发，无签名便携 ZIP 足以验证产品，不为规避已知安全提示扩大发布系统。
- 云账号、同步、市场和开放式付费代生成：项目不运营素材市场或自动下单系统。朋友定制由 Maxwell 单独沟通范围和验收，不形成自助平台。
- 通用素材生成 Skill：不同宠物的习惯、体型、道具、受力和可接受姿势差异过大，强行自动化会牺牲身份与动作质量。保留内部工具复用，不承诺任意照片自动完成。
- 骨骼、肢体拼接、Hatch Pet、RIFE、光流和自动补间作为主路线：机械连续不等于真实宠物动作自然。
- 动态 WebP 作为唯一运行时格式：不能保证精确逐帧寻址、安全退出、点击区域和 root motion 同步。
