# PRD：petsgraph

## 1. 目标

让用户用自家宠物照片和自行配置的生成服务，制作并安装一只外观一致、动作自然、会在 macOS 桌面上真实左右移动的单宠桌面伙伴。

第一阶段的核心结果不是动作数量，而是一只宠物能以批准的动作图长期运行，并在站立、坐下、躺卧、玩耍、走路、跑步、进食和舔毛之间自然衔接。

## 2. 用户问题

目标用户拥有真实宠物，希望在工作时获得具体宠物的陪伴，而不是通用卡通角色。现有桌面宠物常见问题是：

- 外观只能大致像某种猫狗，无法稳定保留具体宠物的脸型、花纹和体型。
- 动作是互不相关的 GIF 或视频，切换时体型、朝向、承重和尾巴突然变化。
- 走路或跑步只在窗口内部播放，宠物没有在桌面上真正移动，或者窗口移动与脚步不同步。
- 生成、抠图、命名、打包和安装依赖大量隐性人工步骤，无法复用到下一只宠物。

## 3. 第一阶段产品边界

### 3.1 包含

- macOS 单宠运行时，当前显示器底部水平活动带，真实原生窗口左右移动。
- 用户可安装一份本地宠物素材包。
- 站立、坐下、至少两种躺姿、玩耍、走路、跑步、进食和舔毛。
- 左右独立走路与跑步，走路缓慢，跑步至少明显快于走路。
- 有向动作图、安全退出、目标预加载、逐帧寻址、root motion 和自然边缘停车。
- 自主活动、点击或抚摸回应、拖动位置、明确触发玩耍和进食、菜单栏隐藏与退出。
- 用户自行配置 Seedance 等生成服务的本地素材制作流程。
- 人工验收驱动的动作、图边和整链批准记录。

### 3.2 不包含

产品级 Non-Goals 见 `CORE.md`。第一阶段尤其不做多宠互动、跨显示器、二维自由漫游、云账号、素材市场和运行时生成。

## 4. 核心体验

### 4.1 外观

- 目标是“身份真实，允许轻度风格化”，不追求照片级毛发复制。
- 必须稳定保留宠物脸型、体型、花纹、耳朵、眼睛、尾巴和左右差异。
- 用户在默认显示尺寸和真实桌面背景上无需名字即可确认这是自己的宠物。

### 4.2 活动

- 宠物大部分时间停留在稳定姿态循环中，动作节奏安静，不持续抢夺注意力。
- 行为调度先产生移动、休息、玩耍、进食或清洁等意图，再沿动作图执行完整短序列。
- 动作不能按固定间隔随机硬切。普通切换等待安全退出，跨姿态变化播放批准的有向过渡。

### 4.3 桌面移动

- 向左走或跑时原生窗口向左移动，向右时向右移动。
- 窗口 y 固定在当前显示器底部安全活动带。
- 走路速度来自走路素材的 root motion；跑步速度来自跑步素材，原型验收要求跑步平均速度至少约为走路的 2 倍。
- 宠物到达屏幕边缘前提前减速、停步并进入稳定姿态；后续可以通过批准的转向动作向反方向移动。

### 4.4 互动

- 素材质量优先于互动数量。
- 第一阶段只提供足够支撑陪伴感和控制权的互动：点击或抚摸回应、拖动、玩耍、进食、隐藏和退出。
- 交互不得绕过动作图或强迫普通过渡中途硬切；直接拖动、锁屏和隐藏是明确强中断。

## 5. 素材生产原则

- 先验证一条真实上桌的完整动作链，再扩充动作覆盖。
- 一个生产单元可以是较长连续母片，并从中切出多个运行时片段。
- 左右方向分别生成。充足额度用于独立方向、完整有向过渡和受控重试，不用于一次批量生成大量候选。
- 每个动作或过渡最多 3 次受控尝试。每次必须有明确变化假设，不能只换随机种子重复抽取。
- 每次只验收一个生产单元；单项通过后才进入相邻图边和整链验收。
- Skill 最终必须把输入照片、provider 调用、后处理、QA、人工暂停点和安装包编译串成可复用流程。

## 6. 推荐生成顺序

生成顺序按最早暴露承重风险排列，不按动作观赏性排列：

1. 建立身份参考集：正面、左右侧全身、站姿、坐姿、躺姿、脸部、尾巴和显著花纹特写。
2. 生成并验收右向 `站立→走路→跑步→走路→站立`，同时完成透明边缘和 root motion 上桌验证。
3. 独立生成左向同链，确认真实左右特征，不使用镜像补齐。
4. 补正面站立与左右站立之间的转向边，形成完整移动入口。
5. 依次完成 `站立↔坐下`、`坐下↔趴卧`、`趴卧↔左右侧躺`。
6. 为每个稳定节点补可长期停留的循环。
7. 依次完成舔毛、进食和玩耍有限活动，每次只验收一个生产单元。
8. 完成全图可达性、关键路径整链、30 分钟调度和安装包验收。

前一个阶段未通过时，不开始后一个阶段的批量素材生产。

## 7. 成功指标

### 6.1 Phase 0 阻塞闸门

右向链 `站立→起步→慢走→加速→快跑→减速→慢走→停步→站立` 必须同时满足：

1. 用户在默认显示高度与真实桌面背景上确认宠物身份、体型和花纹连续。
2. 每段动作和每个接缝均无明显身体缩放、四肢错误、尾巴硬跳、镜头变化或透明边缘闪烁。
3. 动画帧和真实窗口使用同一时间轴，走跑方向正确，跑步平均速度至少约为走路的 2 倍。
4. 支撑脚相对桌面的机械漂移 P95 目标不超过 2pt；该指标只是预警，最终仍需人工确认无滑步感。
5. 到屏幕边缘前自然减速并停住，无撞边、瞬移、突然反向或恢复后漂移。
6. 整链达到 `runtime-chain-approved` 后才进入完整素材扩展。

### 6.2 第一阶段完成标准

1. 一份单宠包覆盖全部第一阶段必备动作，左右正式素材独立，并通过包验证。
2. 从默认稳定姿态可以到达所有必备能力，并有批准路径返回稳定姿态。
3. 动作、图边和关键整链均有结构化人工验收记录，未批准候选不会进入正式运行。
4. 用户连续观察至少 30 分钟，未发现随机硬切、明显身份漂移、重复抽搐式切换或不可解释的移动。
5. 用户可以完成点击或抚摸、拖动、玩耍、进食、隐藏和退出，不影响正常桌面使用。
6. 素材制作过程能够从一组输入照片稳定产出可安装包，失败、重试与用户验收均可追溯。

## 8. 关键假设 / Red-Team

| 承重假设 | Fails if | 最便宜测试 | Kill criterion |
|---|---|---|---|
| 更多 Seedance 额度可以换来更高质量 | 多次生成仍不收敛到相同端点，只产生更多随机候选 | 先做右向完整链，每次重试只改变一个明确变量 | 同一动作或边 3 次仍未通过，停止该策略并改变生成单元、约束或模型 |
| 连续视频母片可以切出自然循环和过渡 | 镜头移动、主体缩放或没有可闭合步态周期 | 用一条站立到走路再停步的固定镜头母片提取 start/loop/stop | 无法从连续直接帧得到闭合循环时，不扩其他位移动作 |
| root motion 可以让真实窗口与脚步同步 | 原生窗口更新、帧显示和 provider 动作节奏使用不同时间轴 | 用右向走跑链做真实窗口采样与人工慢放 | 无法达到方向正确、跑步约 2 倍速度且无明显滑步时，暂停运行时选型 |
| 左右独立生成可以保护真实身份 | 输入缺少两侧参考，生成结果仍把花纹换侧或重画 | 先为同一动作生成左右两份并在真实尺寸比较 | 任一方向无法被用户认作同一宠物时，不允许用镜像或另一方向替代 |
| 素材 Skill 能复用到其他宠物 | 第一只成功依赖未记录手修和作者记忆 | 第一只完成后用第二只高辨识度宠物复跑 | 需要隐性逐帧修图或跳过标准闸门时，只能称为定制流程，不能发布为通用 Skill |

## 9. Pre-Mortem

### Tigers，第一阶段阻塞项

- 动作内部自然但无法接上目标循环，导致整链仍然硬跳。
- 逐帧抠图在毛发、尾巴和快速四肢上闪烁，充足生成额度也无法解决后处理问题。
- 素材全部生成后才上桌，重复 petsdesk 的验证顺序错误。
- 运行时使用速度标量或高频 IPC 近似窗口位移，脚步和窗口长期漂移。
- 候选、批准母片和已安装片段状态混乱，未通过素材被误装。

### Paper Tigers，暂不扩大投入

- 动态 WebP 与图集的最终选择。PNG 序列保留为事实源后，运行时格式可以通过原型数据决定。
- 多宠性能与宠物间碰撞。第一阶段单宠，不应提前设计。
- 全平台抽象。包契约可以保持平台中立，但运行时先证明 macOS。

### Elephants，需要持续观察

- 左右参考照片是否足够覆盖真实花纹和体型。
- 人工验收是否因动作数量增加而疲劳，降低后期标准。
- 轻度风格化在不同毛色和犬种上是否仍能保持身份。
- 第二只宠物是否暴露第一只流程中的隐性定制步骤。

## 10. 当前未知

- macOS 运行时最终采用 Swift/AppKit，还是 Tauri/Rust 加原生运动时钟。
- 默认窗口尺寸、活动带高度和用户缩放范围。
- 逐帧语义分割 provider 与本地后处理的最终组合。
- 首个宠物的身份参考集和具体动作生成提示协议。

这些未知项不改变产品方向，应由 Phase 0 最小链证据决定。
