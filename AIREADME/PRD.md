# PRD：PetsGraph 安静陪伴 MVP

> 当前状态：PetsGraph macOS `0.5.10` 同时内嵌五百与飞流两个低功耗宠物包，均为 `runtime-chain-approved`、`installable=true`，双宠桌面人工验收和单 DMG 公开发布已完成。Windows `0.6.0` 仅面向 Windows 11 x64 和内部朋友，已完成 .NET 10 WPF 实现、本机交叉编译、真实双包校验、GitHub Windows Runner 和朋友真机使用验收，发布所有者已授权以无签名便携 ZIP 发布。

## 1. 产品目标

在受支持的本地桌面上长期放置一只或多只像真实宠物、动作自然、不会打扰工作的数字宠物。它们大部分时间各自睡觉，偶尔按各自节奏自然换睡姿；用户点击某只宠物时，只让它醒来面向用户坐好，再次点击后回去睡觉。macOS 与 Windows 11 x64 使用不同原生宿主，但共享不改变的宠物包与核心行为契约。

首个版本验证的不是桌面宠物能做多少事，而是用户是否愿意让它整天留在桌面上。App 继续使用稳定名称 `PetsGraph`，但素材生产不追求通用化。五百、飞流及未来受托宠物可以拥有完全不同的姿势、道具、动作图和随机权重。

## 2. 用户问题与产品洞察

用户需要的不是效率工具，也不是需要照料的游戏角色。桌面宠物本身不产生工具价值，它的价值来自熟悉宠物持续存在所带来的陪伴感。

本项目已经证明走路、跑步和真实窗口移动可以实现，但实际观察后，最舒服的体验来自五百安静睡觉和缓慢更换睡姿。过多移动、点击目的地和命令式交互会抢夺注意力，也会增加崩溃、窗口消失、镜像和方向错误等风险。

因此，第一款产品从“完整桌面宠物能力集”收敛为“高质量睡眠陪伴”。

## 3. 目标用户与核心 Job

首批目标用户是 Maxwell 和喜欢这些真实猫狗的朋友。他们希望在工作时看到熟悉的宠物安静地陪在桌面上，不需要先理解桌面宠物工程或素材包结构。朋友如希望加入自己的宠物，可以委托 Maxwell 进行一次独立定制，而不是使用自动上传照片流程。

核心 Job：当我长时间面对电脑工作时，我希望偶尔看见熟悉的宠物正在自然睡觉，让桌面有生命感，但不需要我持续操作或照料。

## 4. MVP 范围

### 4.1 默认行为

- 启动后进入已批准的稳定睡姿，不先站立或巡游。
- 新启动默认放在物理屏幕左下角，地面锚点贴合屏幕底边。
- 宠物在睡姿中长期停留，只在随机时间请求下一种睡姿。验收用串行闭环只用于检查素材和接缝，不代表正式运行顺序。
- 随机调度在已经人工通过的有向图上游走，使用长尾间隔、最小停留时间、节点权重、场景粘性、近期两姿势去重和活动冷却，不能固定节拍轮播，也不能从十个循环中随机硬切。
- 普通地面睡眠与枕头睡眠都是核心场景。
- 枕头场景具有粘性。进入后应连续停留并更换枕头睡姿，不能刚进入就立即离开或频繁让枕头出现和消失。

具体时间分布由真实 30 分钟观察决定，不在素材 clip 中硬编码。

### 4.1.1 多宠装载与独立时钟

- 首次安装默认装载全部内嵌宠物，当前是五百和飞流。
- 菜单栏可以分别装载或隐藏每只宠物，也可以一次全部装载或全部隐藏。隐藏某只宠物不影响另一只的行为。
- 五百和飞流各自维护随机长尾计时、当前节点、近期睡姿和待执行目标。一只宠物换姿、被点击或被指定睡姿时，另一只不跟随变化。
- App 共享低开销渲染 scheduler，但不共享行为状态。卸载释放该宠物窗口与媒体缓存，重新装载从默认睡姿开始。
- 装载选择与每只宠物位置在下次启动时恢复。首次默认布局为屏幕左下角横排，五百左一、飞流左二、互不重叠。

### 4.2 点击

- 点击睡眠中的宠物：请求醒来并进入当前场景对应的正面坐姿。
- 点击坐着的宠物：请求回到当前场景的睡眠图。
- 普通过渡一旦开始，不被后续普通点击硬切。运行时只保留一个尚未开始的点击目标，避免请求堆积。
- 点击后的首个可见醒来反应目标为 1 秒内，完整坐起目标为 3 至 6 秒。最终以动作自然和真实桌面人工验收为准。
- 点击只命中宠物本体。透明区域与枕头不触发宠物点击。
- 不监听宠物之外的桌面点击，不记录移动过程中的外部鼠标事件。

### 4.3 指定睡姿

- 菜单栏提供「选择睡姿」，按地面与枕头场景列出 10 种中文睡姿。
- 菜单、当前状态和操作反馈不显示节点 ID、clip ID 或边 ID。
- 睡眠中选择姿态后沿动作图到达目标。坐着时选择姿态，先自然返回睡眠，再进入目标路径。
- 已经开始的有限过渡不可被截断。用户再次选择时，只保留最后一个目标，完成当前过渡后继续。
- 指定睡姿不能绕过安全退出、预加载、道具连续性和完整过渡规则。
- 五百包显示 10 种睡姿；飞流包按自己的 9 个自主睡姿生成菜单，不复用固定十姿势目录。

### 4.4 拖动与窗口

- 用户可以从宠物本体按住并拖到当前桌面的任意位置，包括靠近屏幕边缘和 Dock 区域。
- 拖动时猫与当前场景道具作为一个透明窗口整体移动。
- 用户松手后，宠物从兼容稳定姿态继续运行，不自动吸回桌面底部。
- 宠物自己的动作最多进行水平位移，不能改变用户放置的垂直位置。
- 宠物保持在普通窗口和 Dock 前方，同时不获取键盘焦点。
- 每只宠物独立拖动和持久化。用户手动把两只宠物放到重叠位置是允许的，运行时不自动碰撞或分离。

### 4.4.1 全局大小

- 菜单栏提供 `0.5×`、`0.75×`、`1.0×`、`1.25×`、`1.5×`、`1.75×`、`2.0×` 七档全局大小。
- 1.0× 以当前五百显示大小为参照。飞流使用自己的包级基准，在同一倍率下视觉体型略大于五百。
- 调整立即作用于全部已装载宠物，并用于之后重新装载的宠物。倍率跨启动持久化，不提供单宠独立倍率。
- 缩放保留当前动作和地面接触点，不让宠物跳回默认睡姿，也不因窗口越界而消失。

### 4.4.2 Windows 11 x64 平台范围

- 以 .NET 10 WPF 提供无边框透明置顶窗口和系统托盘菜单，不改变宠物包的动作图、时间、坐标或批准媒体。
- 只支持 Windows 11 x64，以 self-contained 便携 ZIP 分发给知情朋友。用户完整解压后直接运行 `PetsGraph.exe`，无需预装 .NET。
- 当前不做 MSIX、安装器或代码签名。用户必须理解未签名应用可能出现 SmartScreen 提示，并通过可信渠道与 SHA-256 核对产物。
- GitHub Windows Runner 的编译、测试和 PE/ZIP 检查不证明真实桌面体验。v0.6.0 另有朋友在真实 Windows 11 x64 上完成使用验收并反馈没有问题；因未附分项时长或 DPI 日志，只记录该最终人工结论。

### 4.5 普通睡眠场景

首个包优先复用已经通过素材验收的稳定姿态和有向边，包括：

- 趴卧
- 左侧蜷卧
- 香箱
- 左侧伸展
- 仰卧
- 蜷缩仰卧
- 松散半仰卧
- 睡眠香箱

随机调度只从已批准、可无限停留且完整接入图的节点中选择。某个素材已经通过不代表它自动进入 MVP。

### 4.6 道具睡眠场景

道具睡眠不是装饰层，而是每只宠物动作图中的独立视觉场景。五百使用枕头，飞流使用猫窝，二者不要求共享相同节点或路径。

- 猫和当前道具在运行时第一版作为同一组已批准画面播放，不把枕头或猫窝拆成独立物理对象。
- 从普通场景进入时允许宠物在过渡视频中短距离移动。该动作只服务于睡眠场景切换，不恢复通用巡游功能。
- 靠枕 B 已冻结为正式网关 `gateway.pillow.b`，并通过短循环、相邻接缝和真实桌面链验收。
- 网关不参与随机睡姿抽选，只负责进入、离开、预加载和点击醒来的汇合。
- 网关必须有自然的短循环，避免预加载或等待期间停在一张静止图片上。
- 枕头内部随机更换睡姿应优先使用直接有向边，不应每次都回到网关并重新醒来。
- 枕头场景使用独立的 `sit.front.pillow`，坐起后枕头继续保留在同一位置和尺度。
- `0.2.0` 不生成 B2。未来只有新的真实桌面证据证明现有网关不适用时，才以新包版本增加替代节点。
- 飞流的猫窝场景新增 `sit.front.cat-bed`。它是坐在同一只猫窝里的正面稳定坐姿，只承担猫窝场景的点击目标；它设置 `role=interaction`、`autonomousEligible=false`，不会在自然睡眠中被随机抽中。
- 飞流从猫窝睡姿点击醒来时，先经猫窝蜷睡到达 `sit.front.cat-bed`；再次点击后，从该坐姿回到猫窝蜷睡。普通地面睡姿仍使用 `sit.front.floor`，不能让猫窝在点击时突然消失。
- `rest.cat-bed.curled` 是猫窝内部的睡姿枢纽，普通随机换姿经它到达猫窝自然趴睡、猫窝侧伸睡或猫窝舒展露腹睡，不经过坐姿。

## 5. 状态与动作图

产品层只请求意图，运行时负责沿图完成动作：

```text
sleeping
  → waiting-for-safe-exit
  → preload-edge-and-target
  → changing-sleep-pose
  → sleeping

sleeping
  → waking
  → 当前场景坐姿，例如 sit.front.floor、sit.front.pillow 或 sit.front.cat-bed
  → returning-to-sleep
  → sleeping
```

节点分为三种职责：

- `dwell`：可以被自主调度选择并长期停留的睡姿。
- `gateway`：场景进出和路径汇合，只短暂停留。
- `interaction`：点击后的坐姿或其他明确用户响应，不参与自主睡姿随机。

职责必须进入数据契约，不能只靠节点名称猜测。

飞流动作图采用两个随机子图和两个非随机坐姿入口。当前人工通过的素材关系为：

```text
sit.front.floor ↔ 平趴睡
                    ↔ 紧蜷睡
                    ↔ 侧身伸展睡
                    ↔ 半仰睡 ↔ 仰躺睡
                    ↔ 猫窝蜷睡 ↔ sit.front.cat-bed
                                   ↔ 猫窝自然趴睡
                                   ↔ 猫窝侧伸睡
                                   ↔ 猫窝舒展露腹睡
```

这里的双向符号代表两条独立生成和独立验收的有向边。运行时每次只从当前节点的合法邻居中按权重选择，并通过图规划到达目标。`rest.floor.prone.right` 是地面随机枢纽，`rest.cat-bed.curled` 是猫窝随机枢纽。地面与猫窝的场景切换直接发生在平趴睡和猫窝蜷睡之间，不经过猫窝坐姿。仰躺睡通过半仰睡接入地面子图，所以从仰躺睡点击醒来到地面坐姿时，合法路径是仰躺睡、半仰睡、平趴睡、正面坐姿。两个坐姿都不参与自主随机。当前图共有 11 个节点、20 条有向边和 31 个唯一素材。此前毛毯踩奶素材作为历史候选保留，但首版猫窝图不接入踩奶，未来如要恢复必须先设计与猫窝一致的新活动。

## 6. 素材生产边界

- 一个生产单元处理一个稳定动作、一个有向过渡或一条可以确定性拆分的连续母片。
- 核心素材可以在用户明确授权下进行多次受控尝试，不设置固定三次上限。
- 每次尝试必须说明相对上一版改变的失败假设、动作分解、端点、画布、提示约束或模型策略。
- 同一失败连续出现时，必须改变生成单元或动作设计，不能只换 seed 重复抽取。
- 所有候选、任务 ID、seed、提示词、输入哈希、处理脚本、人工结论和拒绝原因完整保留。
- 身份、动作、接缝、整链和真实桌面运行分别验收。机械报告不能升级人工状态。
- 每只宠物可以采用不同数量的睡姿、不同场景、不同道具和不同枢纽。内部工具只复用任务账本、抠图、完整性、坐标、验收和打包基础设施，不假设动作语义通用。
- 静态图服务用于身份基准、姿态设计、安全画布和视频首尾端点。Seedance 继续负责连续动作视频。静态图无论来自 Seedream 还是 `gpt-image-2`，都不能替代视频动作与接缝验收。

## 7. 成功指标

### 7.1 核心体验

1. 在真实桌面连续观察至少 30 分钟，宠物至少约 80% 的时间处于稳定睡眠节点。
2. 睡姿变化没有硬切、体型跳变、尾巴突变、异常醒来或固定节拍轮播感。
3. 用户无需查看名字即可持续认出当前宠物，脸型、体型、花纹、耳朵、眼睛和尾巴在关键路径中保持一致。
4. 枕头、猫窝等场景道具不会在同一场景内突然出现、消失、缩放或改变与宠物的接触关系。
5. 点击睡眠中的宠物后，目标是在 1 秒内出现可见醒来反应，并自然进入当前场景正面坐姿。
6. 再次点击后自然返回睡眠，不经过与场景无关的站立或走跑链。
7. 用户可以把宠物拖到桌面任意位置，松手后位置稳定，窗口仍位于普通窗口与 Dock 前方。
8. 30 分钟运行中无崩溃、窗口消失、无限过渡、点击请求堆积或不可恢复状态。
9. 朋友可以从 Release 下载 DMG，在 Apple 芯片、macOS 14 及以上环境完成安装，并理解首次打开的系统安全提示。
10. 用户可以只通过中文菜单识别并到达当前宠物包声明的全部可选睡姿，切换过程中不出现内部 ID 或硬切。
11. 同一用户会话只运行一个 PetsGraph 进程，重复启动立即退出。进程内可按用户选择显示多只宠物，但不能因重复启动生成重复的五百或飞流窗口。
12. 低功耗正式版在普通睡眠稳定态目标为不高于 2% CPU 和 80 MiB，连续过渡目标为不高于 3% CPU 和 128 MiB。测量必须只统计唯一当前版本 PID，并排除旧 AppTranslocation 实例污染。
13. 随机运行至少观察 60 分钟，不能出现固定串行顺序、最近两个姿势立即回访或场景来回抖动。
14. 飞流在猫窝场景点击后必须坐在同一只猫窝里，猫窝的形状、尺度、位置和明暗连续；再次点击能自然回到猫窝睡眠。
15. 首次安装同时显示五百和飞流时，两只宠物在物理屏幕左下角横排，五百在左、飞流在右、互不重叠，且飞流视觉体型略大。
16. 两只宠物连续运行至少 60 分钟，各自随机换姿时间不锁步，装载、隐藏、指定睡姿、拖动或缩放一只时不破坏另一只状态。
17. Windows 用户可以完整解压 ZIP，运行 x64 `PetsGraph.exe`，看到五百和飞流，并通过托盘完成显示、隐藏、睡姿、全局大小和退出。
18. Windows 11 在常见 DPI 缩放下必须保持透明区鼠标穿透、宠物本体命中、拖动不跳位、当帧可见内容不越界，且重启后恢复位置和全局倍率。

### 7.2 发布闸门

1. 所有进入默认调度的循环和过渡具有批准配方与完整性哈希。
2. 所有睡姿都能到达当前场景的点击坐姿，并能返回睡眠。
3. 网关、交互节点和不可中断过渡不会被随机调度器当作普通睡姿。
4. 普通场景、枕头场景、猫窝场景分别按当前宠物包实际声明完成正常速度、慢放和真实桌面链验收。
5. 拖动、点击、随机换姿、锁屏恢复、隐藏和退出完成真实 AppKit 验收。
6. MVP 包达到 `runtime-chain-approved` 后才能标记 `installable=true`。
7. 公开草稿的全部附件必须匹配仓库内清单的字节数和 SHA-256，App 可执行文件必须严格为 `arm64`。
8. GitHub Actions 重新运行完整测试并验证附件后，才能把草稿 Release 发布为最新版。
9. Windows 代码必须通过锁定依赖、.NET 单元测试、WPF 编译、AMD64 PE、ZIP 结构和真实双包完整性校验。
10. Windows 候选只有在真实 Windows 11 x64 完成透明、DPI、点击、拖动、托盘、边界、锁屏恢复和 60 分钟运行闸门，并获得明确发布授权后，才能上传到 GitHub Release。

### 7.3 `0.3.1` PNG 基线验收结论

- 53 个 clip、14 个节点、39 条边完成正式包编译和完整性校验。
- 7 个普通睡眠节点和 3 个枕头睡眠节点均可自主停留；10 条醒来路径和 10 条返回路径可达。
- 45 项 XCTest 通过，覆盖包完整性、中文名称、指定睡姿、行为契约、安全退出、预加载、点击去抖、禁止默认走跑和左下角启动。
- 真实桌面连续观察 30 分 36 秒，无崩溃、窗口消失、硬切、请求堆积、道具跳变或不可恢复状态。

## 8. PM Red-Team 结论

| 承重假设 | Fails if | 最便宜验证 | 改变方向的标准 |
|---|---|---|---|
| 现有靠枕 B 可以承担网关 | 默认尺寸下姿势别扭，或相邻边无法自然起步 | 拼一条现有 B 停留 1 秒的真实桌面短链 | 人工仍把它看成异常半坐，或短循环无法闭合时才生成 B2 |
| 随机换姿会增加陪伴感 | 切换过于频繁，用户开始注意调度器而不是宠物 | 真实时间运行 30 分钟并记录姿势和场景切换 | 用户觉得被打扰，或出现固定轮播感时扩大停留区间并减少姿势 |
| 通过网关唤醒不会显得迟钝 | 点击后长时间没有任何可见回应 | 从路径最深的睡姿点击并计时 | 1 秒内没有醒来迹象时补更直接的醒来边或提高安全退出密度 |
| 枕头可以作为合成画面而非独立对象 | 点击区域、拖动边界或接触关系无法区分猫和枕头 | 用猫体命中区和猫枕联合屏幕边界做桌面测试 | 枕头误触频繁或必须独立碰撞时再升级道具模型 |
| 窄功能 MVP 足够成立 | 30 分钟后用户觉得只有睡觉缺少生命感 | 先完成安静版本，不提前恢复走跑 | 只有真实长期观察提出明确缺口时才增加低频活动 |

## 9. 暂时不做

- 点击桌面空白处让宠物走过去。
- 自主走路、跑步、巡游、追随鼠标或屏幕边缘往返。
- 玩耍、进食、舔毛和复杂命令菜单。
- 多宠互动、碰撞、自动避让、养成、数值、提醒、云同步和素材市场。多宠独立并列显示已经进入正式版，但宠物之间仍不互动。
- 面向陌生用户的一键照片上传、自动选择通用姿势、自动生成完整动作图和自助安装包。
- Intel Mac、Windows on Arm、Windows 10 和 Linux 安装包。Windows 11 x64 只提供当前无签名便携 ZIP，不扩展为其他 Windows 载体。
- 将已经批准的走跑素材删除或伪装成未完成。它们保留为后续能力，但不进入 MVP 默认行为。
