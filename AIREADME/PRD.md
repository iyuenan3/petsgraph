# PRD：PetsGraph 纪念陪伴 Player 与定制 PetPack

> 状态：产品方向与 PetPack 1.0 公开契约已经实现，Apple Silicon macOS 与 Windows x64 零素材 Player 已冻结为 `v1.0.0` 源码和双平台附件。macOS 已完成人工验收，Windows 已完成机械验证但本轮没有真实 GUI 复验；五百与飞流 PetPack 1.0 仍是私有候选，不随 Player 发布。历史 `v0.6.0` 继续作为内嵌双宠的旧架构回滚版本。

## 1. 产品目标

为宠物离世后的主人提供一种低打扰、可长期保存的桌面纪念陪伴。客户把宠物生前照片、视频和习惯资料交给 Maxwell，获得一份属于这只宠物的 `.petpack`；开源 PetsGraph Player 在本地安静播放它的生活片段。

核心体验不是复活、模拟意识或让宠物执行命令，而是让主人熟悉的样子、动作节奏和小习惯重新拥有时间。

## 2. 目标用户与核心 Job

主要用户是经历宠物离世、希望保留日常陪伴感的主人。猫和狗都属于正式支持范围，第三只制作对象是猫小葵。

核心 Job：当我工作或使用电脑时，我希望偶尔看见熟悉的宠物按照自己的节奏睡觉、换姿或做生前常见的小动作，不需要我操作它，也不希望它像低帧率桌面精灵一样卡顿、闪动或突然换姿。

## 3. 价值主张

- 这是某一只具体宠物，不是换皮的通用猫狗。
- 视频正常速度下具有连续生命感，不靠骨骼、补帧或硬切制造动作数量。
- 用户拥有并长期保存 `.petpack`，不依赖账号、订阅、云端授权或服务持续运营。
- Player 免费开源，客户付费购买的是身份还原、连续视频生产、抠图、动作图设计和人工验收服务。

## 4. 产品结构

### 4.1 PetsGraph Player

- 公开源码、免费下载、离线运行。
- 安装包不包含五百、飞流、小葵或任何客户宠物素材。
- 当前实现目标只覆盖 Apple Silicon macOS 与 Windows x64。
- 同时装载零只、一只或多只宠物。
- 管理内部宠物库、固定位置透明播放、独立行为时钟、统一缩放、显示隐藏和卸载。
- 不包含 Seedance、Seedream、GPT Image 生产逻辑、提示词、任务记录或 provider 凭据。

### 4.2 私有制作系统

- 管理客户原始资料、身份母版、动作设计、Seedance 任务、抠图、几何锁定、评审和包编译。
- 制作工具、客户目录、正式宠物素材与生产参数保持私有。
- 工具可以复用，但每只宠物的身份、姿态、场景、动作图、基础体型、时钟和人工验收分别定制。

### 4.3 `.petpack`

- 一个包只描述一只猫或狗。
- 是客户付费获得并自行长期保存的数字纪念作品。
- 包含最终媒体、动作图、行为配置、基础体型和完整性信息。首个 1.0 不带官方签名，未来格式可以增加可选来源证明。
- 不包含原始照片、提示词、脚本、动态库、provider 配置或运行时网络地址。
- 格式平台无关，当前由 macOS 与 Windows Player 消费，未来 iPadOS 与电视端 Player 仍应读取同一包。

## 5. Player 用户体验

### 5.1 装载

装载是导入，不是引用原文件路径：

1. 用户选择一个或多个 `.petpack`。
2. Player 验证格式、路径安全、媒体能力与完整性；未来格式声明签名能力时再验证来源信息。
3. 复制到 Player 管理的内部宠物库，并从内部副本播放。
4. 用户可以把原始 `.petpack` 移到云盘、移动硬盘或其他长期保存位置。

相同 `packageId` 与相同版本不重复装载；更高 `contentVersion` 作为同一宠物更新，保留位置和可见状态；更低版本默认拒绝降级。任何失败都不能破坏当前可用版本。

### 5.2 多宠与独立时钟

- 所有已装载宠物在 Player 启动后自动恢复。
- 每只宠物有独立行为会话、当前节点、随机时钟、停留截止时间和近期动作状态。
- 多只宠物可以同时切换动作，Player 不统一错开行为，也不让一只宠物影响另一只。
- 宠物之间不互动、不碰撞、不避让，也不共享动作图。
- 动作权重、停留时间范围和默认节点属于 `.petpack`；共享渲染调度只提供时间和绘制机会。

### 5.3 固定位置与拖动

- 新装载宠物出现在不与现有宠物重叠的默认位置。
- 用户可以从宠物可见身体区域拖动并保存独立位置。
- 透明区域点击穿透，单击宠物不触发任何动作。
- 宠物视频始终在固定舞台内播放，窗口不会因走路、转身或场景变化产生自主桌面位移。
- 所有片段共享明确的底部中心锚点和固定几何，不按逐帧 Alpha 包围盒重新居中。

### 5.4 显示与隐藏

- 隐藏不会删除内部宠物包。
- 显示状态按宠物持久化，Player 重启后继续遵守，避免投屏期间宠物意外出现。
- 视觉上立即隐藏；如果宠物正在不可中断过渡，后台完成到下一个稳定节点后暂停时钟和解码。
- 再次显示前先完成当前帧解码，从稳定状态继续，不能出现黑帧、闪动或半个动作。
- “全部显示”和“全部隐藏”只作用于已装载宠物。

### 5.5 卸载

- 卸载停止播放并删除 Player 内部正式副本、缓存、位置和可见状态。
- 不触碰用户保存在外部的原始 `.petpack`。
- 再次使用必须重新提供原始文件。
- 卸载单只或全部都需要明确确认；卸载全部的提示必须列明之后需要原始 `.petpack` 才能恢复。

### 5.6 全局大小

- 全局倍率范围为 `0.5` 至 `2.0`，默认 `1.0`。
- 所有已装载宠物同时缩放，不提供单宠倍率。
- 最终大小等于宠物包基础体型乘以全局倍率，因此不同猫狗的既定相对体型不会被抹平。
- 缩放围绕每只宠物的底部中心锚点进行，不重启动作、不切片段、不改变固定位置。

### 5.7 菜单

```text
装载宠物包…

显示宠物
  全部
  <每只已装载宠物>

隐藏宠物
  全部
  <每只已装载宠物>

卸载宠物
  全部
  <每只已装载宠物>

大小
  0.5 至 2.0

关于 PetsGraph
退出 PetsGraph
```

- 宠物名称动态读取自 `.petpack`，Player 不写死五百、飞流或小葵。
- “显示宠物”中已显示项置灰，“隐藏宠物”中已隐藏项置灰。
- 无可操作宠物时对应“全部”置灰。
- 即使全部宠物隐藏，菜单栏或系统托盘入口仍然存在。
- “关于 PetsGraph”显示当前版本，并说明开源 Player 与独立 `.petpack` 内容的边界。
- 菜单不提供动作、睡姿、场景、声音或行为控制。

### 5.8 声音

Player 1.0 完全静音。未来呼噜声等音频只能作为可选包能力增加，默认关闭，并且不得让旧包突然发声。不得生成宠物说话或用声音制造宠物仍有意识的暗示。

## 6. 定制服务与素材输入

### 6.1 客户输入

- 身份照片：正面、两侧、全身、花纹、耳朵、尾巴、爪子和体型关系。
- 行为视频：睡觉呼吸、走路、醒来、起身、趴下、吃饭、舔毛和观察周围。
- 习惯说明：常见睡姿、喜欢的地点和道具、动作节奏、特殊小习惯，以及主人明确不希望出现的内容。

视频解决“动起来是不是它”，照片解决“长得是不是它”。素材不足时必须区分证据充分、身份可还原但行为需合理生成、无法达到最低标准三种结论，不能用相似的通用猫狗替代。

### 6.2 最小可交付体验

- 至少两个可长期观看的稳定休息状态。
- 至少一个体现该宠物习惯的生活场景，例如吃饭、舔毛或看向窗外。
- 所有运行时实际连接都有独立生成并通过的有向过渡。
- 所有循环、过渡和完整链在正常速度下通过主人视觉验收。
- 正式播放保持 `1.0x`，动作速度在生成阶段已经缓慢自然。
- 完成统一抠图、固定几何、透明边缘验收和真实 Player 长时间观察。
- 最终交付一份可离线保存、带完整性信息的 `.petpack`。

定价不按视频数量简单计算。额外场景、额外道具、额外生活动作、未来音频或联合双宠画面可以形成新的定制范围。

### 6.3 客户资料

- 每个客户和每只宠物使用独立私有目录保存源资料、生产过程、评审与交付物。
- 默认不用于模型训练、公开展示或案例宣传，案例展示必须另行授权。
- 暂定从最终交付日起保留一年。用户自行保存的 `.petpack` 是长期主副本。
- 正式接单前需要补充客户授权、保留到期、删除或延期、再次交付和退款修改规则。

## 7. 素材与生命感标准

- 身份连续：脸、花纹、体型、耳朵、尾巴和毛发在完整链中保持同一只宠物。
- 物理连续：爪子、身体重心、承重点、尾巴和道具接触不跳变。
- 时间连续：呼吸相位、目光、动作速度和停顿自然延续。
- 画面连续：位置、尺度、光线、透明边缘和场景道具不闪动。
- 稳定状态使用可无限停留的连续视频循环；状态变化使用专门的有向过渡视频。
- 只有稳定帧、完整呼吸周期边界、自然遮挡或完全离场才能成为候选切点。
- 未抠图完整链先验收，抠图后再以浅色、深色、棋盘格和真实桌面复核完整链。
- 如果连接可见，素材必须重新生成或重新切分，播放器不承担修补职责。

## 8. 成功指标

### 8.1 核心体验

1. 主人在正常速度下持续认出这只宠物，并认为动作节奏和小习惯像它。
2. 循环重复观看和任意合法过渡均无可感知卡帧、闪动、硬切、尺寸跳变、身份漂移或透明边缘抖动。
3. 用户愿意让一只或多只宠物安静显示一整天，不需要操作或照料。
4. 多只宠物各自按独立时钟运行，位置和全局倍率在重启后正确恢复。
5. 装载后外部 `.petpack` 移动或离线不影响播放；Player 升级不丢失或改写内部宠物包。
6. 隐藏、显示和卸载的语义清楚，不发生投屏意外显示或误以为卸载后仍可无文件恢复。

### 8.2 发布闸门

1. 每个正式包通过格式、路径、完整性、动作图和媒体可读性校验；未来签名格式另加来源校验。
2. 所有必需循环、边和完整图在正常速度下获得明确人工通过。
3. 原生帧率、正式倍率、连续原始帧状态和速度处理记录完整。
4. Apple Silicon macOS 与 Windows x64 使用同一 `.petpack` 得到一致身份、时序、锚点和连接结果。
5. 多宠并发分别测试 2、4、8 只及同时过渡，发布说明据真实性能给出推荐数量，不在包协议设置收费式数量上限。
6. Player 更新、包更新失败、坏包、重复包和卸载全部均有不破坏现有可用宠物的回归测试。

## 9. 关键假设与风险

- Value: 离世宠物主人愿意长期观看连续生活片段，而不是只保存照片和原视频。第三只小葵需要以真实长时间使用验证。
- Usability: 用户能理解装载、隐藏和卸载区别，并会自行长期保存 `.petpack`。交付说明必须明确备份责任。
- Viability: 定制服务成本来自生成迭代、抠图和人工验收，不能在第三只完整生产成本未知时承诺固定低价或无限修改。
- Feasibility: `cropped-rgba-clips` 已作为跨平台长期兼容基线，但包体积较大；小葵完整链以后只验证可选紧凑表示，不能阻塞五百、飞流转换或破坏旧包兼容。
- Trust: 离世纪念场景对身份错误、突然发声、营销话术和资料泄露高度敏感，默认必须克制、离线和私有。

## 10. 暂时不做

- 点击互动、动作选择、睡姿菜单和宠物任务。
- 窗口随动作移动、自主巡游和点击目的地行走。
- 多宠互动、关系、碰撞或跨包同步动作。
- 云账号、云同步、在线素材市场和强 DRM。
- 自动把任意照片生成完整宠物包的自助服务。
- 声音、iPadOS、电视端、Intel Mac、32 位 Windows、Windows on Arm 和 Linux。
