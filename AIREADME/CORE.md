# CORE：PetsGraph

## 身份

PetsGraph 是面向宠物离世纪念场景的安静陪伴产品。客户提供宠物生前照片、视频与习惯资料，由 Maxwell 逐只定制连续视频宠物包；开源的 PetsGraph Player 只负责在本地装载并播放 `.petpack`，不内置任何真实宠物素材。

产品不是宠物模拟器，也不宣称宠物仍有意识。主人不需要操作、喂养或指挥宠物，只会在桌面固定位置看到它按照自己的节奏睡觉、换姿、吃饭、舔毛或看向窗外。

## 使命

把一只具体宠物生前真实的样子、动作节奏和生活习惯，制作成可以由主人长期保存、离线播放的数字纪念作品，让静态照片之外的日常陪伴感得以延续。

## 当前状态

- 已发布的 `v0.6.0` 是旧架构事实：Apple Silicon macOS 与 Windows 11 x64 Player 均内嵌五百和飞流，仍包含点击坐立、睡姿菜单和历史 root motion 能力。
- 下一代架构已经完成产品决策，PetPack 1.0 的公开契约、参考验证器、合成夹具和五百飞流私有候选已经实现。Apple Silicon macOS `0.7.0-dev` 也已完成零素材 Player、canonical 库、被动行为与固定舞台的机械实现；真实 macOS 桌面人工验收、Windows x64 重构、双平台运行时验收和正式交付仍待实现。
- 项目物理根继续固定为 `petsgraph/`。目标目录、Git 边界和当前文件迁移已经完成；详细状态见 `DIRECTORY.md`。
- 五百与飞流是已经发布的历史正式包，现已用批准媒体离线转换为 PetPack 1.0 私有候选，媒体逐字节保持。候选仍等待新 Player 双平台运行时验收，不能作为正式交付。小葵只整理已经存在的身份与部分连续动作资料，本轮不继续生成、抠图或制作 PetPack。
- 当前实现与目标架构必须在文档中显式标注，不得把规划写成已发布能力，也不得用旧实现反向限制新契约。

## 目标交付边界

- PetsGraph Player 开源、免费、离线运行，发布包中不包含任何宠物素材、客户资料、生成工具或 provider 凭据。
- 一个 `.petpack` 只描述一只猫或狗，包含最终运行媒体、动作图、独立时钟参数、基础体型和完整性清单，不包含脚本、原始照片、提示词或可执行代码。首个 1.0 不带来源签名，后续格式可以增加可选官方签名。
- 用户收到 `.petpack` 后自行长期保留。装载是导入操作，Player 校验后复制到内部宠物库；外部文件随后可以移动到云盘、移动硬盘或其他长期存储位置。
- 卸载会删除 Player 内部保存的该宠物包、缓存、位置和可见状态。再次装载必须重新提供原始 `.petpack`。
- Player 可以同时装载多只宠物。每只宠物拥有独立动作图、独立随机时钟、固定桌面位置和自己的包级基础体型，不产生宠物间互动，也不共享行为状态。
- 用户可以拖动每只宠物的位置。宠物动作始终发生在固定舞台内，窗口不因走路或其他视频 root motion 移动。
- 大小是 Player 级统一设置，范围为 `0.5` 至 `2.0`。最终大小等于包级基础体型乘以全局倍率，所有已装载宠物同时缩放并保持各自底部中心锚点。
- 菜单只提供装载宠物包、按单只或全部显示宠物、按单只或全部隐藏宠物、按单只或全部卸载宠物、统一大小和退出。
- Player 1.0 不播放声音。未来呼噜声等音频只能作为可选包能力增加，不能让旧包失效或突然发声。
- 当前开发和发布只覆盖 Apple Silicon macOS 与 Windows x64。iPadOS 与电视端属于未来 Player，但今天交付的 `.petpack` 必须保持平台无关和长期可读。

## Non-Goals（明确不做）

- 不做点击坐立、指定动作、指定睡姿、任务、喂养、亲密度、签到或其他宠物交互。
- 不做宠物间互动、碰撞、关系状态、自动避让或跨包联合动作。
- 不做跨桌面自主行走、窗口跟随动作移动、点击目的地移动或 root motion 驱动的桌面巡游。
- 不做任意用户上传照片后自动生成完整宠物包的自助平台。制作工具可以复用，但身份、动作、场景、图拓扑和验收必须逐宠定制。
- 不做云账号、强制联网、订阅校验、素材市场或强 DRM。未来官方签名只用于来源和完整性，不用于限制客户离线使用。
- 当前不做 Intel Mac、32 位 Windows、Windows on Arm、Linux、iPadOS 或电视端实现。
- 当前不做声音。未来音频不能采用未经客户确认的通用合成叫声或宠物说话。

## 绝不 / Hard Constraints

- 真实宠物身份、动作质量、生命感和主人正常速度观看结论优先于动作数量、自动化程度、文件体积与机械指标。
- 正式动作只使用 Seedance 等视频模型直接生成的连续原始视频帧。骨骼、精灵图、肢体拼接、RIFE、光流、自动补间、跨节点倒放和交叉淡化不得进入正式素材路线。
- 呼吸、醒来、起身、趴下和其他动作必须按最终慢速原生生成，正式播放保持 `1.0x`。不得通过后期降速牺牲有效帧率。
- 稳定循环是动作图节点，姿态或场景变化必须有独立生成并人工通过的有向过渡。没有批准过渡的两个片段不得直接切换。
- 运行时不能修补坏素材。不得用淡入淡出、跳帧、重复帧、自动补帧或硬切掩盖身份漂移、承重错误和接缝问题。
- 未抠图完整链先通过身份、动作和接缝验收，再统一抠图。抠图只能改变 Alpha 与边缘颜色，不能重新拟合整段位置、尺度或时间。
- Seedance 纯色背景按整段背景色族处理。若出现无法稳定去除的色相漂移、移动阴影、地面线、纹理或闪烁，应拒绝母片，不靠逐帧参数修补硬救。
- Player 与 `.petpack` 必须离线工作。包内不得包含脚本、动态库、绝对路径、符号链接逃逸、网络地址、provider 配置、原始客户资料或凭据。
- 一旦 `.petpack` 在某个 Player 版本成功装载，其基础播放能力必须在未来 Player 中继续可用。升级不得改写正式包、丢失宠物或强迫客户重新定制。
- 客户资料默认私有，不用于训练或公开展示。每只客户宠物使用独立受控目录，暂定从最终交付日起保留一年；公开案例必须另行授权。
- `player/` 子树和 Player 发布物只包含 Player、PetPack 规范、校验与合成测试资产，不包含真实宠物媒体。根公开 Git 可以在 `codexpets/packages/public/` 保存单独授权的 Codex 宠物图集，但它们不得进入 Player，也不自动采用 MIT License。
- Seedance、Seedream、GPT Image 制作工具、提示词、API 配置、客户目录、正式客户 PetPack 和私有 Codex 包保持私有，并全部位于 `petsgraph/` 根下的受控子树。

## 生命周期

生命周期为 `implementation-in-progress / macos-player-implemented / windows-player-next`。

公开 `v0.6.0` 仍是当前可下载的历史基线，包含五百和飞流，不代表上述新架构已经正式发布。目录迁移、PetPack 1.0 公开契约、五百飞流私有候选转换和 macOS Player 机械实现已经完成；下一阶段重构 Windows x64，再进行两个平台的真实桌面与同包一致性验收。
