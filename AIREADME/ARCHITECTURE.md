# ARCHITECTURE：petsgraph

> 宠物包精确字段见 `SPEC.md`，产品目标见 `PRD.md`，决策理由见 `DECISIONS.md`。

## 目标产品数据流

```text
已批准宠物素材与动作图
  → 包编译器固定变换、哈希与图校验
  → 本地 .petsgraph-pet
  → 离线包加载器
  → 睡眠行为调度器
  → 自主目标或中文菜单指定目标
  → 安全退出与路径规划
  → 下一条边和目标循环预加载
  → 逐帧渲染器
  → AppKit 透明置顶窗口
  → 宠物本体点击与全桌面拖动
```

人工定制制作侧与运行时通过数据包隔离：

```text
受控宠物照片与真实习惯资料
  → 人工设计该宠物自己的姿态、场景、道具和动作图
  → Seedream 或 gpt-image-2 生成静态身份基准、姿态锚点和安全端点
  → Seedance 生成连续视频母片
  → 抠图、固定画布归一化与机械预筛
  → 单动作、图边和完整路径人工验收
  → 批准配方与 PNG 事实源
  → 包编译器与可选低功耗媒体编译器
  → PNG 制作事实源与固定 clip 裁剪 RGBA 正式运行时包
```

## 1. 宠物包与包加载器

`PetsGraphCore` 负责：

- 安全解析 `package.json`、`graph.json`、clip 清单、帧引用和完整性清单。
- 从动作图显式推导必需片段，不依赖目录枚举。
- 拒绝缺失、篡改、符号链接、越界路径和带 hidden 标记的必需文件。
- 验证节点、边、入口出口姿态、安全退出帧、预加载引用和逐帧 root motion。
- 按单调时间直接采样累计 root motion，掉帧后不累加历史 delta。
- 分别验证 `frames`、`hevc-alpha-clips` 和 `cropped-rgba-clips`。raw 模式额外校验固定裁剪矩形、行字节数、帧字节数、总文件长度，以及媒体哈希与完整性清单一致。

包加载成功只证明结构和完整性满足契约，不代表素材已经人工通过，也不代表包可以安装。

## 2. 动作图与节点职责

节点除姿态与朝向外，还必须表达产品职责：

- `dwell`：允许自主调度，必须有可无限停留循环。
- `gateway`：连接场景或汇合路径，只短暂停留，不参与随机抽选。
- `interaction`：点击后的坐姿等明确响应，不参与自主随机。
- `cyclic`：走路或跑步等未来可选活动循环，不属于睡眠 MVP 默认图。

节点还声明 `scene`。首个 MVP 至少支持 `floor` 与 `pillow`。行为层不能把不同场景的节点当成视觉等价节点，尤其不能从枕头睡姿硬切到没有枕头的坐姿。

节点还可以声明 `displayName`。安静陪伴的自主睡姿必须有非空中文名称。`QuietCompanionMenuCatalog` 从图中派生菜单和状态文案，内部 ID 只作为命令参数，不进入用户界面。

普通路径：

```text
stable/current-loop
  → waiting-for-safe-exit
  → preload-edge-and-target
  → playing-directed-edge
  → entering-target
  → stable/target-loop
```

过渡开始后，普通自主请求不能中途改变目标。点击可以替换尚未开始的普通目标，但不能截断已经播放的批准边。

## 3. 睡眠行为调度器

行为层只产生意图，不直接选择 clip：

- 默认意图为 `sleep`。
- 在当前 `dwell` 节点按随机长尾分布停留。推荐起始配置是 20% 为 2 至 5 分钟、60% 为 5 至 12 分钟、20% 为 12 至 25 分钟，最终值属于宠物级行为配置并必须经过真实时间验收。
- 从当前动作图的可达 `dwell` 节点中按宠物级权重选择目标，再由规划器生成完整合法路径。近期两个睡姿进入冷却，当前姿势不能立即重复。
- 枕头场景使用独立的进入概率、最小停留和退出冷却，避免道具频繁出现与消失。
- 场景切换使用低于场景内换姿的权重，并设置最小停留与退出冷却。带道具的活动节点还要设置单独冷却，例如踩奶在一个冷却窗口内最多触发一次。
- `gateway`、`interaction` 和不可中断过渡不进入自主候选集。
- 同一时间最多保留一个尚未开始的用户目标，后到点击可以替换旧目标，不能形成无限队列。
- 菜单指定睡姿与自主调度使用同一个规划器。睡眠中立即请求目标，坐姿先自然返回，有限过渡中只更新最后目标并等待完成。

串行完整链只属于 QA 证据。正式调度不能把该时间线当作播放列表。具体时间、节点权重、近期窗口、场景粘性和活动冷却属于宠物行为配置，不能写死在视频片段、运行时通用代码或帧时长中。

## 4. 点击、拖动与窗口层级

MVP 只处理两类直接操控：

1. 点击宠物本体，在睡眠与当前场景坐姿之间切换。
2. 按住宠物本体拖动透明原生窗口。

目标运行时不监听宠物之外的桌面点击，也不需要辅助功能权限。命中测试必须使用逐帧宠物区域，不能把透明画布或枕头的 alpha 误当成宠物身体。

拖动立即暂停普通行为，清除尚未开始的目标。松手后保留用户设置的 x 和 y，并从兼容稳定姿态恢复。后续任何自主 root motion 都只能在该 y 上改变 x。

AppKit 使用无边框、非激活、透明 `NSPanel`。窗口位于普通窗口与 Dock 前方，加入所有 Space，并且不能抢占键盘焦点。窗口层级通过真实 macOS 桌面验收，不能只从常量值推断正确。

## 5. 道具场景与场景坐姿枢纽

第一版不把枕头建模为独立物理对象。猫与枕头由同一组逐帧画面渲染，但元数据必须区分：

- 猫体点击区域
- 猫与枕头联合可见边界
- 枕头可见区域
- 地面、主体和头部锚点

靠枕 B 已冻结为 `gateway.pillow.b`。它具有独立短循环，只承担场景进出、路径汇合、点击醒来和预加载，并已通过真实桌面接缝验收。

网关只承担普通场景进出、枕头路径汇合、点击醒来和预加载。枕头内部随机换姿优先使用直接有向边，不应每次让五百先回网关醒来。

`sit.front.pillow` 与普通 `sit.front.floor` 是两个视觉上下文节点。二者都面向用户，但前者必须保留同一枕头，不能通过运行时临时叠加道具伪造。

飞流使用独立猫窝场景。`sit.front.cat-bed` 是猫直接坐在同一只猫窝里的完整画面，不是透明猫层与猫窝层的运行时拼接。它承担：

- 猫窝场景的点击坐姿
- 猫窝蜷睡与点击坐姿之间的醒来与返回睡眠
- 下一条边和目标循环的预加载等待

它是 `role=interaction` 且 `autonomousEligible=false`。随机调度不能把它当作睡姿目标，也不能把它作为地面与猫窝场景进出的默认网关。地面平趴睡直接与 `rest.cat-bed.curled` 双向连接。猫窝内部由 `rest.cat-bed.curled` 作为 `role=dwell` 睡姿枢纽，分别连接自然趴睡、侧伸睡和舒展露腹睡；普通随机换姿不让飞流先坐起来。用户点击醒来后停在 `sit.front.cat-bed`，直到再次点击或明确选择睡姿。

猫窝的几何关系由静态端点审计契约约束。制作侧先把每个获批静态端点的编译副本按猫窝宽度、底部中心统一到 2496×1664，再嵌入 960×960 生成安全画布，猫窝锚点为 `(480, 840)`。每个端点或后续整条 clip 只能使用一个固定等比缩放和固定平移，禁止按猫脸、身体或逐帧包围盒重新居中。静态对齐只允许进入视频生产，不等于循环、过渡、抠图或运行时通过。

## 6. 帧渲染与预加载

- PNG/RGBA 序列是制作事实源，v0.3.1 运行时直接逐帧寻址。v0.4.0 从同一事实源生成固定 clip 裁剪的预乘 RGBA 连续帧流。
- 每帧可以有独立时长，播放器不假设全包只有一个 FPS。
- 使用固定最大画布，动作切换时不按 alpha 包围盒调整窗口尺寸。
- 当前 clip、可选出边和目标循环首帧必须在安全退出前完成解析与预加载。
- 解码失败不能降级为硬切、冻结上一帧蒙版或跳到目标第 0 帧。
- 睡眠内部逐帧和终点 root motion 必须严格为零。
- raw crop 只定义存储窗口，CALayer 仍按完整画布坐标放置。镜像时同时镜像 crop 位置和图像内容，命中检测仍在包级画布坐标中解析。
- 小型循环在 36 MiB 预算内预建全部 `CGImage`。长过渡按约 16 MiB 单块、当前块加下一块的方式预建，切换后释放旧块。内存映射数据由图像 provider 持有，不能在当前帧仍显示时提前失效。
- HEVC Alpha 对照只能使用直接视频图层或硬件解码路径。把每帧转成 `CIImage → CGImage → NSImage` 会重新引入高 CPU，不作为默认实现。

## 7. 坐标、道具与 root motion

每个宠物包使用统一运行时画布和坐标。不同母片只允许在编译副本上对整条已批准路径应用一次固定变换，不能逐帧重新居中或修改源帧。

手动拖动偏移与动作 root motion 是两套状态：

```text
windowX(t) = userPlacedX + scale × rootMotionPt.x(t)
windowY(t) = userPlacedY
```

普通睡姿、枕头睡姿、坐姿及其内部过渡 root motion 为零。进入或离开枕头场景时，可以使用已批准的一至两步水平累计 root motion。通用走跑 root motion 继续保留在工程能力中，但睡眠 MVP 行为层不得请求它。

## 8. 人工定制制作侧与运行时边界

私有制作工具负责照片与真实习惯资料、provider 适配、任务账本、母片生成、抠图、固定变换、机械报告、人工验收暂停点和包编译。运行时只消费经过验证的数据包。

这些工具可以共享底层能力，但每只宠物的姿态集合、道具、图拓扑、提示词、端点和行为权重都由人工单独设计。项目不再以“上传任意宠物照片即可自动生成”为架构目标，也不要求飞流复制李五百的节点名称或动作路径。

当前静态图片 provider 配置名为 `GPT_IMAGE_API_KEY`、`GPT_IMAGE_MODEL`、`GPT_IMAGE_GENERATIONS_URL` 和 `GPT_IMAGE_EDITS_URL`。它们只允许由被 Git 忽略的本机配置加载，文档、任务账本和日志只能记录变量名、模型标识、请求摘要与结果哈希，不能记录密钥值或完整认证头。`gpt-image-2` 只用于静态 identity foundation、姿态锚点、安全画布、outpaint 或严格端点参考；Seedance 继续负责正式连续动作视频。

多次生成不设固定全局次数上限，但每次必须有明确假设变化。结果未知时查询原任务，不自动重投。所有失败候选和批准配方保留，不能因方向调整删除历史。

## 9. 公开发布边界

公开代码、媒体和安装包使用不同载体：

```text
Git 标签与仓库内发布清单
  → 草稿 GitHub Release 与版本化附件
  → GitHub Actions 检出精确标签
  → Swift 测试、字节数、SHA-256、arm64 校验
  → 全部通过后发布草稿
```

Git 历史只保存代码、文档、构建工具和小型清单。正式运行时媒体内嵌在 App 的默认宠物包中，Release 只发布 DMG、备用 App ZIP、总览图与校验和，不再重复上传独立素材包。代码使用 MIT License，李五百媒体遵守 `ASSETS.md`。首个公开版只允许 `arm64` 和 macOS 14 及以上。

## 10. 权限、配置与信任边界

- 运行时无账号、会话、服务端、数据库或网络 API。
- 运行时不读取 Seedance、TOS 或其他 provider 凭据。
- 生成凭据只存在于用户本机环境、钥匙串或被忽略配置，不进入包、Git、日志和 AIREADME。
- MVP 不需要辅助功能权限，不安装全局桌面点击监听。
- 宠物包是不受信任输入，必须先验证路径、schema、文件类型和哈希，再允许加载。
- 原始宠物照片、生成母片、任务账本、失败候选和真实桌面录屏默认属于私有工作区。只有编译后的正式宠物包和经过选择的总览图作为 Release 附件公开。

本项目没有邮件、定时服务、公开 SEO 页面、Webhook、内嵌 Agent 或运行时自动化，因此不创建对应的平行文档。私有素材制作流程由 Maxwell 主动发起，不是桌面应用内的自动 Agent。

## 11. 验证现状与边界

2026-08-10 使用完整 Xcode 对正式 v0.3.1 真实执行 45 项 XCTest，0 失败。正式 `0.3.1` 包另行通过加载器、6,925 条完整性记录和动作图校验，全部帧与 `0.3.0` 哈希一致。

v0.4.0 真实执行 57 项 XCTest，0 失败。固定裁剪正式包通过 53 个 clip、6,866 帧、1.827 GB 媒体完整性与逐帧可读校验；真实桌面普通睡眠约 1.3% 到 1.6% CPU、53 MiB，连续随机换姿约 2.1% 到 2.7% CPU、19 到 46 MiB。另有一次 `ps` 读数约 112 MiB，说明 mapped 文件的 RSS 与 `top` physical footprint 口径不同，性能记录必须保留测量工具。发布所有者明确授权把该确定性衍生包晋级为 `runtime-chain-approved` 与 `installable=true`，v0.3.1 PNG 正式包继续作为回滚基线。

| 已有覆盖 | 当前证据 | 边界 |
|---|---|---|
| `0.1.0` 与 `0.2.0` 包解析、hidden、缺失、篡改、符号链接和哈希拒绝 | `PackageLoaderTests` | 不替代媒体视觉验收 |
| scene、role、行为配置、自主候选池、点击往返与不可中断策略 | `QuietCompanionPlannerTests` | 只保证图和状态机约束 |
| 安全退出、目标预加载、完整逐帧播放与严格零睡眠 root motion | `PackageLoaderTests`、`GraphPhaseTests` | 不证明动作本身自然 |
| 点击去抖、坐姿往返、禁止走跑和物理屏幕左下角启动 | `BasicBehaviorSessionTests` | 不替代真实 AppKit 操作 |
| 中文菜单、睡眠中指定、坐姿指定和不可中断过渡排队 | `BasicBehaviorSessionTests`、`PackageLoaderTests` | 系统状态栏菜单树仍需真实用户环境观察 |

人工闸门已经完成：正常速度和慢放素材整链、真实桌面点击、全桌面拖动、Dock 前方层级、Space、锁屏恢复，以及 30 分钟无崩溃、消失、硬切、请求堆积、道具跳变或不可恢复状态。Maxwell 最终结论为“通过”。

后续修改只要影响素材、图路径、点击命中、窗口层级、默认位置或计时参数，就必须重新执行对应人工闸门。测试绿色不能自动继承本次 `runtime-chain-approved` 结论。

## 12. 禁改项 / Forbidden Refactors

- 不把生成 provider、账号、额度或网络调用放入桌面运行时。
- 不把已搁置的点击目的地移动重新包装成 MVP 默认行为。
- 不用全局鼠标监听替代宠物窗口内点击和拖动。
- 不退化成平面动作 ID、固定时长轮播或随机硬切。
- 不把网关和交互节点加入随机睡姿池。
- 不让枕头在同一场景中无过渡出现、消失或改变尺度。
- 不用整个猫枕联合 alpha 作为宠物点击区域。
- 不用固定速度标量、CSS 内部平移或独立计时器代替逐帧 root motion。
- 不默认镜像正式左右素材。
- 不把动态 WebP 或 MP4 设为唯一运行时事实源。
- 不静默混入失败抠图帧、未批准候选或没有生产履历的素材。
- 不在运行时代码中写死某只宠物的十种姿势、猫窝或枕头拓扑。差异进入宠物包的图和行为配置，但不承诺任何两只宠物共享相同图。
- 不把验收串行片当作正式随机播放列表，也不从十个循环中直接随机硬切。
- 不把静态生图结果当作正式动作视频，或让静态 provider 直接写入可安装批准状态。
