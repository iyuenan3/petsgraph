# ARCHITECTURE：PetsGraph

> PetPack 对外字段见 `SPEC.md`，目标目录与 Git 跟踪边界见 `DIRECTORY.md`，产品意图见 `PRD.md`，决策理由见 `DECISIONS.md`。本文件同时记录目标架构与当前 `v0.6.0` as-built，任何实现声明必须标注所属状态。

## 1. 状态分层

| 层 | 状态 | 含义 |
|---|---|---|
| 目标产品 | 部分实现 | PetPack 1.0、双宠私有候选和双平台零素材 Player 已实现；正式交付与双平台人工验收仍待实现 |
| PetPack 1.0 公开核心 | 已实现，双平台已接入 | schema、标准库验证器、基线与前向兼容合成夹具、确定性构建和安全回归；Swift 与 C# 原生实现通过同一测试向量与真实候选 |
| 五百与飞流 PetPack 候选 | 已机械验证、待运行时验收 | 旧批准媒体逐字节转换，排除交互与窗口 root motion，尚未进入 approved 或 delivery |
| 当前公开版 | 已实现、已发布 | `v0.6.0` 内嵌五百与飞流，使用 schema `0.4.0` `.petsgraph-pet` |
| 第三只宠物 | 部分素材完成 | 小葵已有身份与部分连续动作基础，尚未形成 PetPack 1.0 可交付包 |

新代码以目标产品为准。旧代码、媒体和发布物继续作为迁移输入与历史回滚事实，不能被规划性文档冒充已经完成的新实现。

## 2. 目标组件

```text
Private PetsGraph Studio
  客户资料
  身份与动作设计
  Seedance / 静态参考 provider
  未抠图整链评审
  抠图与固定几何
  PetPack 编译（签名后续）
             ↓
       customer-owned .petpack
             ↓ import
Public PetsGraph Player
  PetPack Core
  Managed Pet Library
  Behavior Sessions
  Render Scheduler
  Platform Shells
```

### 2.1 Public Player

目标 `player/` 子树和 Player 发布物只包含：

- PetPack 规范、解析器、验证器和一致性测试。
- 多宠行为、装载事务、显示隐藏、卸载、全局大小和固定舞台渲染。
- Apple Silicon macOS 与 Windows x64 原生宿主。
- 不含真实宠物身份的合成测试包与坏包样例。
- 构建、测试、打包、安装和开源发布文档。

目标 `player/` 不再包含正式五百、飞流、小葵或客户 PetPack 媒体，也不包含客户资料、Seedance/Seedream/GPT Image 生产工具、提示词、任务账本或 API 配置。根公开 Git 可以在隔离的 `codexpets/packages/public/` 保存单独授权的 Codex 图集；当前仓库和 v0.6.0 中已经公开的五百、飞流历史素材保留原有限定授权，迁移时不抹除历史。

### 2.2 Private Studio

私有制作系统位于项目根 `studio/`，负责客户输入、provider 适配、任务幂等、身份母版、连续视频生产、正常速度人工评审、背景色族抠图、固定几何、批准履历和包编译，未来再负责官方签名。根公开 Git 忽略整个目录，Studio 不创建独立 Git 仓库，也不是公开仓库的 submodule。

Studio 输出纯数据 `.petpack`。Player 不调用 Studio，也不知道 provider、任务 ID、提示词和客户目录。

### 2.3 PetPack Core

平台无关核心负责：

- 容器与规范相对路径读取。
- schema、完整性、媒体能力和首版无签名约束验证。
- 节点、边、可达性、安全退出与行为配置。
- 装载、重复检测、版本更新和原子注册。
- 每宠独立时钟与动作图状态。
- 全局倍率与每宠固定锚点的逻辑换算。

macOS 与 Windows 可以使用不同语言实现，但必须通过同一批 PetPack 测试向量和状态机一致性用例。共享的是公开契约与验证证据，不强求共用 UI 或渲染代码。

当前 `petpack/` 已实现普通 ZIP 容器预算、跨平台安全路径、完整性覆盖、固定舞台、clip、动作图、被动行为和原始 RGBA 媒体长度验证，并提供不含真实身份的确定性基线包与前向兼容包。后者声明未知可选能力并省略权重覆盖，验证 Player 忽略未知可选能力且使用默认权重 `1.0`。macOS 与 Windows 原生实现都已接入同一契约，完成 canonical 库、更新事务、原始 RGBA 映射、被动行为会话和固定舞台渲染。原生校验、测试和应用构建通过仍不等于真实桌面视觉验收通过。

## 3. 目标数据流

### 3.1 装载

```text
用户选择一个或多个 .petpack
  → 临时位置安全解析
  → schema / 路径 / 完整性 / media capability 校验
  → package ID 与 content version 冲突处理
  → 复制 canonical copy 到 Player 管理库
  → 回读验证
  → 原子注册
  → 创建独立 Pet Session 与固定舞台
```

Player 不能只保存用户原文件路径。用户在装载后移动或删除外部文件，不影响内部已装载宠物。

### 3.2 播放

```text
每宠独立随机时钟到期
  → 从包级权重选择合法自主目标
  → 图规划器寻找有向路径
  → 等待当前循环安全退出
  → 预加载下一条边和目标循环
  → 完整播放边
  → 进入目标循环
  → 重新计算该宠物自己的停留时间
```

共享渲染 scheduler 可以向全部实例提供单调时间和绘制 tick，但不能共享随机目标、当前节点或停留截止时间。多只宠物允许同时过渡。

## 4. 多宠宿主

每只已装载宠物拥有：

- 唯一 package ID 与 content version。
- 独立固定舞台或透明窗口。
- 独立行为会话、随机状态、当前节点和独立时钟。
- 独立桌面位置和可见状态。
- 独立媒体缓存和解码状态。
- 包级基础体型。

Player 级共享状态只包括：

- 一个进程与平台菜单入口。
- 全局 `0.5` 至 `2.0` 显示倍率。
- 低开销渲染调度与资源预算。
- 内部宠物库和版本索引。

宠物之间不互动、不碰撞、不避让、不共享图和时钟。协议不设置商业数量上限，具体 Player 发布说明根据 2、4、8 只同时运行与同时过渡的测试公布推荐数量。

## 5. 固定舞台与窗口

- 用户拖动只改变宠物实例的固定屏幕锚点。
- 所有媒体使用包级参考画布和底部中心锚点。
- 最终显示比例为包级基础体型乘以 Player 全局倍率。
- 窗口位置不读取视频 root motion，也不因步行、转身、场景或 clip 切换移动。
- 宠物可以在固定画布内挪步、转身、离场或入场，但不能推动原生窗口跨桌面移动。
- 透明区域点击穿透；宠物可见主体提供拖动命中，但单击不触发动作。
- 缩放保持每只宠物底部中心的屏幕位置，不重启动作、不改变包媒体和固定几何。
- 新装载宠物先使用不重叠默认布局，用户拖动后允许重叠。

Player 不能根据逐帧 Alpha 包围盒重新居中或缩放主体。抠图和 clip 存储裁剪只能改变像素与存储窗口，不能改变统一画布中的既定位置。

## 6. 显示、隐藏与卸载

可见状态和装载状态是两套正交状态：

```text
loaded + visible
loaded + hidden
unloaded
```

- 隐藏立即从屏幕移除画面，但保留 canonical copy、位置和可见状态记录。
- 如果正在不可中断边，渲染隐藏后后台完成到稳定节点，再暂停行为时钟与解码。
- 再次显示先预加载当前稳定帧，再恢复该宠物自己的时钟。
- 显示状态跨 Player 重启持久化，全部隐藏时菜单栏或系统托盘仍然可用。
- 卸载停止实例并删除内部 canonical copy、缓存、位置和可见状态。再次使用必须重新提供外部 `.petpack`。
- 卸载全部必须明确确认，并且失败不能形成半删状态。

## 7. 菜单与用户控制

菜单模型固定为：

```text
装载宠物包…

显示宠物
  全部
  <动态宠物列表>

隐藏宠物
  全部
  <动态宠物列表>

卸载宠物
  全部
  <动态宠物列表>

大小
  0.5 至 2.0

退出 PetsGraph
```

Player 不提供动作、睡姿、场景、互动或声音菜单。宠物名来自包，不能写死在平台 UI。显示或隐藏菜单按当前状态禁用无意义项，卸载使用明确确认。

## 8. 视频动作图

稳定循环是节点，有向过渡是边。行为层只选择目标节点，不能直接选择文件或把视频数组随机硬切。

关键状态：

```text
stable-loop
  → waiting-safe-exit
  → preloading-edge-and-target
  → playing-directed-edge
  → entering-target
  → stable-loop
```

- 有限边开始后不可中断。
- 没有边的节点不可直接切换。
- 预加载失败时继续当前稳定循环。
- 反向动作使用另一条正式边，不使用倒放。
- Scene 和紧密道具是包级视觉语义，不由 Player 写死 `floor`、`pillow`、`cat-bed` 等枚举。
- QA 完整链只是遍历证据，不是运行时播放列表。

## 9. 媒体与生命感

正式媒体要求：

- 直接生成连续视频原帧，正式倍率 `1.0x`。
- 呼吸、醒来、起身和趴下按最终慢速原生生成。
- 身份、承重、尾巴、目光、道具接触、光线和画面尺度在完整链中连续。
- 未抠图完整链先通过，再统一进行片段级背景色族抠图。
- 同一片段使用一个抠图参数族和一个固定几何，不逐帧重新拟合。
- Player 不提供淡入淡出、补帧、改速、硬切或重复帧兜底。

首个 PetPack `formatVersion=1.0.0` 要求每个 clip 恰好声明一个固定裁剪的预乘 RGBA 连续帧流 `cropped-rgba-clips`。以后可以用显式新格式版本增加可选 representation，由平台选择自己明确支持的版本，但不能让五百、飞流或已经交付的 1.0 基础表示失效。

## 10. 持久化与升级

应用二进制、canonical 宠物库和 cache 必须分离：

```text
Application
  Player binary and resources

User Data
  library-or-Library/<package-id>/<content-version>/<archive-sha>.petpack
  cache-or-Cache/<package-id>/<content-version>/<archive-sha>/...
  staging-or-Staging/...
  registry.json
  settings.json
```

- Player 更新只能替换应用二进制和可重建 cache，不能修改 canonical copy。
- 普通卸载 Player 默认保留宠物库；彻底删除数据必须单独确认。
- 相同 package ID 的新版包原子替换，更新失败继续使用旧版。
- 位置与可见状态按 package ID 保存，全局大小按设备保存。
- macOS 数据根为 `~/Library/Application Support/PetsGraph/`，内部目录使用 `Library/`、`Cache/` 和 `Staging/`；Windows 数据根为 `%LOCALAPPDATA%\PetsGraph\`，内部目录使用 `library/`、`cache/` 和 `staging/`。两个平台都在数据根保存 `registry.json` 与 `settings.json`，这些平台路径不能写入包。

## 11. 安全与信任边界

- PetPack 是数据，不是插件。禁止脚本、动态库、可执行文件和代码入口。
- 导入拒绝绝对路径、越界、符号链接、未知必需能力、哈希不匹配和无法解码的必需媒体。
- 包不包含 API key、签名 URL、provider endpoint、客户源资料或生产目录。
- 首个 1.0 包不带签名，完整性哈希只发现损坏和内部不一致。官方签名以后通过显式格式契约加入，证明来源但不承担 DRM。
- Player 不需要账号、联网生成、遥测、云同步或辅助功能权限。
- 全部宠物隐藏时仍保留控制入口，投屏隐私状态在重启后保持。

## 12. 当前实现与历史 `v0.6.0`

已发布的 `v0.6.0` 仍具有这些旧行为：

- `v0.6.0` 的 Swift/AppKit 与 .NET/WPF 都从安装包内发现五百、飞流 `.petsgraph-pet`；当前 main 的两个新 Player 都不再直接加载旧包。
- schema `0.4.0` 使用固定 clip 裁剪的预乘 RGBA 连续帧流。
- 每只宠物已有独立窗口、行为会话、随机时钟和位置，全局七档倍率已经存在。
- 菜单仍包含宠物装载、点击坐立和指定睡姿等旧交互。
- 两个平台的历史标签代码都包含 root motion、点击交互或指定动作；当前 main 的新实现已经删除这些目标外能力。
- Windows `v0.6.0` 是 .NET 10 WPF self-contained x64 ZIP，macOS 是 Apple Silicon DMG。

这些能力继续由历史 Release、测试和 Git 保护。新重构不能把旧发布物改写成不存在，也不能因删除目标交互而删除批准媒体与生产履历。

macOS `0.7.0-dev` 当前机械实现包括严格 ZIP 与 ZIP64 校验、store 与 deflate、完整性和媒体长度校验、不可变 canonical copy、可重建 cache、幂等导入、升级确认、降级拒绝、卸载、每宠独立行为会话、隐藏到稳定节点后暂停、固定舞台、透明命中拖动、全局七档倍率、动态菜单和状态持久化。它已经构建为不含 `.petpack` 的 Apple Silicon ad-hoc 签名 App，并用公开合成包和两个私有真实候选完成原生校验。

Windows x64 `0.7.0-dev` 已用 C# 与 WPF 实现相同边界，并增加 RGBA 到 WPF `Pbgra32` 的显式通道转换、单实例托盘宿主、零宠物启动、多包导入和 self-contained AMD64 便携 ZIP。19 项 MSTest、全解决方案 Release 构建、公开基线、前向兼容与 deflate 合成包、两个私有真实候选的原生校验，以及零宠物 ZIP 结构和 PE 架构检查均已通过。两个平台的安装索引都会重新验证包 ID、版本和摘要，损坏索引不能把内部路径导向数据根之外。

以上都是机械证据。真实桌面正常速度观看、菜单操作、透明命中、DPI、多显示器、多宠长时性能、隐藏恢复、应用升级保留和双平台同包视觉一致性仍需人工验收。

## 13. 迁移边界

可直接复用：

- 一包一宠、独立行为会话、共享低开销 scheduler。
- 动作图、安全退出、预加载、完整有向过渡和完整性验证。
- 固定裁剪 RGBA 的媒体事实、底部锚点和低功耗经验。
- macOS 与 Windows 原生透明窗口、菜单入口、位置持久化和全局倍率。
- 已批准媒体、生产履历、双平台测试与 Release 回滚事实。

macOS 与 Windows 已完成以下机械切换，后续工作转入人工验收和发布加固：

- 内嵌宠物发现改为外部 `.petpack` 导入与内部宠物库。
- 点击、指定睡姿和 interaction 命令改为纯自主行为。
- root motion 驱动窗口改为固定舞台。
- 当前菜单改为显示、隐藏、卸载和统一大小。
- 在同一 `petsgraph/` 项目根下，用明确子树和根 Git 忽略分离公开 Player、私有制作、宠物事实源、PetPack 与 Codex 衍生产物；Studio 不建立独立 Git 仓库。
- 已使用离线转换器把五百、飞流的旧 schema `0.4.0` 批准包转换为 PetPack 1.0 候选，并通过公开验证器、媒体摘要映射和确定性重建。新 Player 不长期实现旧 schema 运行时兼容层，旧版继续由不可移动标签和 Release 回滚。

明确废弃：

- 新目标中的宠物点击动作、动作菜单、窗口跟随步行和桌面自主巡游。
- 在 Player 发布包中内嵌五百、飞流或任何客户宠物。
- 运行时调用生成服务或读取私有生产配置。

## 14. 禁改项 / Forbidden Refactors

- 不得把私有 Studio 代码或客户资料移入公开 Player 仓库。
- 不得把 `.petpack` 变成可执行插件或在线授权容器。
- 不得让 Player 升级删除、重编或原位修改 canonical 宠物包。
- 不得为了减少实现量恢复硬切、倒放、补帧、淡入淡出或随机视频数组。
- 不得用一套固定猫动作模板限制猫狗或所有客户宠物。
- 不得把多宠独立时钟合并成全局行为状态。
- 不得提供单宠倍率并破坏已经确认的全局大小语义。
- 不得在隐藏状态重启时意外显示宠物。
- 不得把当前 `v0.6.0` 的历史发布事实写成已经使用 PetPack 1.0，也不得用新参考验证器的实现否认旧版本仍可下载和回滚。
- 不得在项目根使用会递归清理 ignored 内容的 Git 清理命令，也不得重新创建职责不明的根 `workspaces/`；后续私有目录迁移与清理必须遵守 `DIRECTORY.md` 的逐切片清单、哈希和回读门禁。
