# ARCHITECTURE：petsgraph

> 宠物包精确字段见 `SPEC.md`，产品目标见 `PRD.md`，决策理由见 `DECISIONS.md`。

## 目标产品数据流

```text
已批准宠物素材与动作图
  → 包编译器固定变换、哈希与图校验
  → 每只宠物一个本地 .petsgraph-pet
  → 离线多包加载器与宠物管理器
  → 每只宠物独立睡眠行为会话与随机时钟
  → 自主目标或该宠物中文菜单指定目标
  → 安全退出与路径规划
  → 下一条边和目标循环预加载
  → 共享 24 Hz 渲染调度器
  → 每只宠物独立的 AppKit 或 WPF 透明置顶窗口
  → 宠物本体点击、全桌面拖动与全局等比缩放
```

人工定制制作侧与运行时通过数据包隔离：

```text
受控宠物照片与真实习惯资料
  → 人工设计该宠物自己的姿态、场景、道具和动作图
  → Seedream 或 gpt-image-2 生成静态身份基准、姿态锚点和安全端点
  → Seedance 生成连续视频母片
  → 抠图、固定画布归一化与机械预筛
  → 单动作、图边和完整路径人工验收
  → 批准配方与 PNG 事实源
  → 包编译器与可选低功耗媒体编译器
  → PNG 制作事实源与固定 clip 裁剪 RGBA 正式运行时包
```

## 双宠运行时

v0.5.10 在不改变单包动作图语义的前提下增加一个 App 级管理层：

- `Resources/Pets/` 可以内嵌多个 `.petsgraph-pet`。每个包仍只描述一只宠物，包 ID 与宠物 ID 必须唯一。
- `AppDelegate` 为每只已装载宠物创建独立 `PetWindowController` 与 `BasicBehaviorSession`。两只宠物不共享当前节点、随机目标、停留截止时间或用户命令。
- App 只共享一个 24 Hz `Timer`，每个 tick 使用同一个单调时间分别推进各控制器。共享渲染时钟只减少调度开销，不把两只宠物的行为时钟同步。
- 首次安装没有装载偏好时默认装载全部内嵌宠物。启动顺序由宠物 ID 的稳定排序决定，当前固定五百在左、飞流在右，后一只窗口从前一只窗口最大 x 加 12 pt 开始。
- 装载选择、全局大小和每只宠物窗口原点分别写入 `UserDefaults`。卸载会立即关闭窗口并释放控制器与媒体缓存；重新装载从包的默认睡姿开始。
- 全局大小只接受七个离散倍率。每只宠物以自己的 `baseHeightPt` 为 1.0× 基准，因此飞流与五百的既定相对体型不被抹平。缩放保持当前帧 ground anchor 的屏幕位置，不重启行为、不重新选择动作，并在必要时把窗口限制回当前屏幕。
- 透明 `NSPanel` 以 clip 级固定正方形视口呈现，不把 656×224 等制作画布的左右安全留白直接变成桌面窗口。视口变化只发生在 clip 边界，窗口位置由统一制作坐标反算，因此可见宠物不因窗口收紧而跳动。
- 菜单按宠物包声明的 scene 目录动态分组，不再由 App 写死 `floor`、`pillow` 或 `cat-bed`。旧五百包没有 scene 目录时使用兼容中文回退，新包必须声明完整 scene 目录并与图中 scene 精确一致。

当前双宠版本已经完成 67 项 XCTest、84 clip 图验证和 12,013 帧媒体可读校验。真实桌面布局、菜单操作、两只宠物独立随机变化、七档缩放、拖动、猫窝路径、透明边缘与相对体型均已由 Maxwell 验收。飞流基准高度为 181.125 pt，五百为 172.5 pt，二者保持 5% 的相对差异。双宠整日 CPU 与内存继续作为发布后观察项。

## Windows `v0.6.0` 便携宿主

Windows 宿主不修改宠物包或复制行为数据，它以 .NET 10 重新实现同一消费契约：

- `PetsGraph.Core` 负责 schema `0.4.0`、安全路径、完整性、图、行为、时间线、累计 root motion 和固定方形视口。
- `PetsGraph.App` 使用 WPF `WriteableBitmap` 和 `Pbgra32`。包内仍是预乘 RGBA，加载时只做 R/B 通道转换，不重新缩放、定位或修改获批帧。
- 每个 clip 使用与 macOS 相同的固定正方形视口。完整制作画布映射到视口内，presentation offset 移动窗口而不改写媒体坐标。
- 行为会话按 clip facing 对正值累计 root motion 施加左右符号。用户放置原点、动作位移、presentation offset 和当帧边界修正是独立状态。
- `WM_NCHITTEST` 只在当帧 alpha 和 `petHitEllipsePx` 同时命中时返回客户区，其余透明画布和内嵌道具允许鼠标穿透。
- 每只宠物一个透明置顶窗口，共享 24 Hz DispatcherTimer，但保持独立 `QuietBehaviorSession`。位置、显示状态和全局七档倍率写入 `%LOCALAPPDATA%\PetsGraph\settings.json`。
- 正式包当前的道具是 `embedded`，已随 RGBA 帧渲染。Windows `v0.6` 显式拒绝尚未实现的独立 persistent 或 node-scenes 道具，避免静默丢图。
- GUI 使用每用户 Windows Mutex 保证单实例。应用以 `win-x64` self-contained 多文件方式发布，所以用户必须解压完整 ZIP，不能只取出 `PetsGraph.exe`。

## 1. 宠物包与包加载器

`PetsGraphCore` 负责：

- 安全解析 `package.json`、`graph.json`、clip 清单、帧引用和完整性清单。
- 从动作图显式推导必需片段，不依赖目录枚举。
- 拒绝缺失、篡改、符号链接、越界路径和带 hidden 标记的必需文件。
- 验证节点、边、入口出口姿态、安全退出帧、预加载引用和逐帧 root motion。
- 按单调时间直接采样累计 root motion，掉帧后不累加历史 delta。
- 分别验证 `frames`、`hevc-alpha-clips` 和 `cropped-rgba-clips`。raw 模式额外校验固定裁剪矩形、行字节数、帧字节数、总文件长度，以及媒体哈希与完整性清单一致。

包加载成功只证明结构和完整性满足契约，不代表素材已经人工通过，也不代表包可以安装。

## 2. 动作图与节点职责

节点除姿态与朝向外，还必须表达产品职责：

- `dwell`：允许自主调度，必须有可无限停留循环。
- `gateway`：连接场景或汇合路径，只短暂停留，不参与随机抽选。
- `interaction`：点击后的坐姿等明确响应，不参与自主随机。
- `cyclic`：走路或跑步等未来可选活动循环，不属于睡眠 MVP 默认图。

节点还声明 `scene`。scene 是宠物包数据，不是运行时枚举。五百使用 `floor` 与 `pillow`，飞流使用 `floor` 与 `cat-bed`。行为层不能把不同场景的节点当成视觉等价节点，尤其不能从带道具睡姿硬切到没有道具的坐姿。

节点还可以声明 `displayName`。安静陪伴的自主睡姿必须有非空中文名称。`QuietCompanionMenuCatalog` 从图中派生菜单和状态文案，内部 ID 只作为命令参数，不进入用户界面。

普通路径：

```text
stable/current-loop
  → waiting-for-safe-exit
  → preload-edge-and-target
  → playing-directed-edge
  → entering-target
  → stable/target-loop
```

过渡开始后，普通自主请求不能中途改变目标。点击可以替换尚未开始的普通目标，但不能截断已经播放的批准边。

## 3. 睡眠行为调度器

行为层只产生意图，不直接选择 clip：

- 默认意图为 `sleep`。
- 在当前 `dwell` 节点按随机长尾分布停留。推荐起始配置是 20% 为 2 至 5 分钟、60% 为 5 至 12 分钟、20% 为 12 至 25 分钟，最终值属于宠物级行为配置并必须经过真实时间验收。
- 从当前动作图的可达 `dwell` 节点中按宠物级权重选择目标，再由规划器生成完整合法路径。近期两个睡姿进入冷却，当前姿势不能立即重复。
- 枕头场景使用独立的进入概率、最小停留和退出冷却，避免道具频繁出现与消失。
- 场景切换使用低于场景内换姿的权重，并设置最小停留与退出冷却。带道具的活动节点还要设置单独冷却，例如踩奶在一个冷却窗口内最多触发一次。
- `gateway`、`interaction` 和不可中断过渡不进入自主候选集。
- 同一时间最多保留一个尚未开始的用户目标，后到点击可以替换旧目标，不能形成无限队列。
- 菜单指定睡姿与自主调度使用同一个规划器。睡眠中立即请求目标，坐姿先自然返回，有限过渡中只更新最后目标并等待完成。

串行完整链只属于 QA 证据。正式调度不能把该时间线当作播放列表。具体时间、节点权重、近期窗口、场景粘性和活动冷却属于宠物行为配置，不能写死在视频片段、运行时通用代码或帧时长中。

多宠运行时为每只宠物创建一份行为会话并分别调用 `start(at:)`。一个宠物的随机换姿、点击、菜单命令或过渡完成不能修改另一只宠物的状态。共享渲染 scheduler 只能提供当前单调时间，不能共享随机目标或下一次换姿截止时间。

## 4. 点击、拖动与窗口层级

MVP 只处理两类直接操控：

1. 点击宠物本体，在睡眠与当前场景坐姿之间切换。
2. 按住宠物本体拖动透明原生窗口。

目标运行时不监听宠物之外的桌面点击，也不需要辅助功能权限。命中测试必须使用逐帧宠物区域，不能把透明画布或枕头的 alpha 误当成宠物身体。

拖动立即暂停普通行为，清除尚未开始的目标。松手后保留用户设置的 x 和 y，并从兼容稳定姿态恢复。后续任何自主 root motion 都只能在该 y 上改变 x。

AppKit 使用无边框、非激活、透明 `NSPanel`。窗口位于普通窗口与 Dock 前方，加入所有 Space，并且不能抢占键盘焦点。WPF 使用无边框、透明、`Topmost`、不出现在任务栏的 Window，并通过 Win32 命中测试实现透明区穿透。两个平台的窗口层级、透明命中和拖动都必须在各自真实桌面验收，不能只从 API 常量或编译成功推断正确。

## 5. 道具场景与场景坐姿枢纽

第一版不把枕头建模为独立物理对象。猫与枕头由同一组逐帧画面渲染，但元数据必须区分：

- 猫体点击区域
- 猫与枕头联合可见边界
- 枕头可见区域
- 地面、主体和头部锚点

靠枕 B 已冻结为 `gateway.pillow.b`。它具有独立短循环，只承担场景进出、路径汇合、点击醒来和预加载，并已通过真实桌面接缝验收。

网关只承担普通场景进出、枕头路径汇合、点击醒来和预加载。枕头内部随机换姿优先使用直接有向边，不应每次让五百先回网关醒来。

`sit.front.pillow` 与普通 `sit.front.floor` 是两个视觉上下文节点。二者都面向用户，但前者必须保留同一枕头，不能通过运行时临时叠加道具伪造。

飞流使用独立猫窝场景。`sit.front.cat-bed` 是猫直接坐在同一只猫窝里的完整画面，不是透明猫层与猫窝层的运行时拼接。它承担：

- 猫窝场景的点击坐姿
- 猫窝蜷睡与点击坐姿之间的醒来与返回睡眠
- 下一条边和目标循环的预加载等待

它是 `role=interaction` 且 `autonomousEligible=false`。随机调度不能把它当作睡姿目标，也不能把它作为地面与猫窝场景进出的默认网关。地面平趴睡直接与 `rest.cat-bed.curled` 双向连接。猫窝内部由 `rest.cat-bed.curled` 作为 `role=dwell` 睡姿枢纽，分别连接自然趴睡、侧伸睡和舒展露腹睡；普通随机换姿不让飞流先坐起来。用户点击醒来后停在 `sit.front.cat-bed`，直到再次点击或明确选择睡姿。

猫窝的几何关系由静态端点审计契约约束。制作侧先把每个获批静态端点的编译副本按猫窝宽度、底部中心统一到 2496×1664，再嵌入 960×960 生成安全画布，猫窝锚点为 `(480, 840)`。每个端点或后续整条 clip 只能使用一个固定等比缩放和固定平移，禁止按猫脸、身体或逐帧包围盒重新居中。静态对齐只允许进入视频生产，不等于循环、过渡、抠图或运行时通过。

飞流当前动作图由两个枢纽和一条半仰分支组成：

```text
地面正面坐姿 ↔ 平趴睡
                   ↔ 侧身伸展睡
                   ↔ 紧蜷睡
                   ↔ 半仰睡 ↔ 仰躺睡
                   ↔ 猫窝蜷睡 ↔ 猫窝正面坐姿
                                ↔ 猫窝自然趴睡
                                ↔ 猫窝侧伸睡
                                ↔ 猫窝舒展露腹睡
```

它包含 11 个节点和 20 条有向边。平趴睡与猫窝蜷睡是自主随机枢纽，两个坐姿是交互节点，仰躺睡只能经半仰睡到达。收爪趴睡与睡眠香箱不在当前图中。串行 41 段时间线只是让全部 31 个唯一素材和全部接缝至少出现一次的 QA 遍历，不是运行时播放列表。

## 6. 帧渲染与预加载

- PNG/RGBA 序列是制作事实源，v0.3.1 运行时直接逐帧寻址。v0.4.0 从同一事实源生成固定 clip 裁剪的预乘 RGBA 连续帧流。
- 每帧可以有独立时长，播放器不假设全包只有一个 FPS。
- 使用固定最大画布，动作切换时不按 alpha 包围盒调整窗口尺寸。
- 当前 clip、可选出边和目标循环首帧必须在安全退出前完成解析与预加载。
- 解码失败不能降级为硬切、冻结上一帧蒙版或跳到目标第 0 帧。
- 睡眠内部逐帧和终点 root motion 必须严格为零。
- raw crop 只定义存储窗口，平台渲染层仍按完整画布坐标放置。macOS 直接消费预乘 RGBA，Windows WPF 在拷贝时转为 `Pbgra32`。镜像时同时镜像 crop 位置和图像内容，命中检测仍在包级画布坐标中解析。
- 小型循环在 36 MiB 预算内预建全部 `CGImage`。长过渡按约 16 MiB 单块、当前块加下一块的方式预建，切换后释放旧块。内存映射数据由图像 provider 持有，不能在当前帧仍显示时提前失效。
- HEVC Alpha 对照只能使用直接视频图层或硬件解码路径。把每帧转成 `CIImage → CGImage → NSImage` 会重新引入高 CPU，不作为默认实现。

## 7. 坐标、道具与 root motion

每个宠物包使用统一运行时画布和坐标。不同母片只允许在编译副本上对整条已批准路径应用一次固定变换，不能逐帧重新居中或修改源帧。

手动拖动偏移与动作 root motion 是两套状态：

```text
windowX(t) = userPlacedX + scale × rootMotionPt.x(t)
windowY(t) = userPlacedY
```

普通睡姿、枕头睡姿、坐姿及其内部过渡 root motion 为零。进入或离开枕头场景时，可以使用已批准的一至两步水平累计 root motion。通用走跑 root motion 继续保留在工程能力中，但睡眠 MVP 行为层不得请求它。

## 8. 人工定制制作侧与运行时边界

私有制作工具负责照片与真实习惯资料、provider 适配、任务账本、母片生成、抠图、固定变换、机械报告、人工验收暂停点和包编译。运行时只消费经过验证的数据包。

这些工具可以共享底层能力，但每只宠物的姿态集合、道具、图拓扑、提示词、端点和行为权重都由人工单独设计。项目不再以“上传任意宠物照片即可自动生成”为架构目标，也不要求飞流复制五百的节点名称或动作路径。

当前静态图片 provider 配置名为 `GPT_IMAGE_API_KEY`、`GPT_IMAGE_MODEL`、`GPT_IMAGE_GENERATIONS_URL` 和 `GPT_IMAGE_EDITS_URL`。它们只允许由被 Git 忽略的本机配置加载，文档、任务账本和日志只能记录变量名、模型标识、请求摘要与结果哈希，不能记录密钥值或完整认证头。`gpt-image-2` 只用于静态 identity foundation、姿态锚点、安全画布、outpaint 或严格端点参考；Seedance 继续负责正式连续动作视频。

多次生成不设固定全局次数上限，但每次必须有明确假设变化。结果未知时查询原任务，不自动重投。所有失败候选和批准配方保留，不能因方向调整删除历史。

飞流精抠采用两阶段几何锁定。粗抠先保守保留主体，并为每个唯一 clip 确定一个整段固定缩放和平移；逐个小闭环人工通过后，该几何不可再变。精抠只清理 alpha 与边缘颜色，不能根据精抠后的包围盒重新定位。当前 12 条问题地面素材经过选择性精抠，19 条已干净素材逐字节复用，完整动作图精抠遍历已由 Maxwell 人工通过。

## 9. 公开发布边界

公开代码、媒体和安装包使用不同载体：

```text
Git 标签与仓库内发布清单
  → 草稿 GitHub Release 与版本化附件
  → GitHub Actions 检出精确标签
  → 对应平台测试、字节数、SHA-256 与架构校验
  → 全部通过后发布草稿
```

Git 历史只保存代码、文档、构建工具和小型清单。正式运行时媒体内嵌在 App 的默认宠物包中。v0.6.0 Release 精确发布一个 Apple 芯片 DMG 和一个 Windows 11 x64 ZIP，不重复发布独立素材包。App 版本为 `0.6.0`，内嵌宠物内容版本保持 `0.5.10`，双平台清单分别固定两层版本。代码使用 MIT License，五百与飞流媒体遵守 `ASSETS.md`。

`codex-pets/` 是一个例外但边界明确的小型分发面。它直接在 Git 中保存两张约 2 MB 的 Codex v2 WebP 图集、对应 `pet.json` 和哈希清单，方便 clone 后校验与安装。该目录不被 PetsGraph App、构建器或 Release 工作流消费，也不改变数百 MB 正式运行时媒体只进入 Release 的规则。

Windows `v0.6.0` 真实双宠 ZIP 由本机从已批准包构建，仓库清单固定名称、字节数和 SHA-256。macOS `v0.6.0` DMG 从同一不可移动标签已经包含的 Swift 宿主、双猫 Logo 和批准宠物包构建。标签保持指向 `ce4570cef6f47fe75b32df40c1476b0657a1d999`，标签后的默认分支只补充双平台清单、打包器版本分离和验证流程，并要求平台源码相对标签无变化。Windows Runner 在草稿阶段复验 ZIP，macOS Runner 在公开后使用只读权限复验全部附件并挂载 DMG。朋友在真实 Windows 11 x64 上完成使用验收并反馈没有问题，该反馈没有附带分项时长或 DPI 日志，所以不把未留证量化结果写成事实。

## 10. 权限、配置与信任边界

- 运行时无账号、会话、服务端、数据库或网络 API。
- 运行时不读取 Seedance、TOS 或其他 provider 凭据。
- 生成凭据只存在于用户本机环境、钥匙串或被忽略配置，不进入包、Git、日志和 AIREADME。
- MVP 不需要辅助功能权限，不安装全局桌面点击监听。
- 宠物包是不受信任输入，必须先验证路径、schema、文件类型和哈希，再允许加载。
- Codex 导出同样按不受信任输入处理。安装工具拒绝未知文件、符号链接、路径越界、哈希漂移、错误图集尺寸和无透明通道的 WebP，并在目标内容不同时默认拒绝覆盖。
- 原始宠物照片、生成母片、任务账本、失败候选和真实桌面录屏默认属于私有工作区。编译后的正式宠物包只内嵌在 App 中，Release 不单独公开素材包。

本项目没有邮件、定时服务、公开 SEO 页面、Webhook、内嵌 Agent 或运行时自动化，因此不创建对应的平行文档。私有素材制作流程由 Maxwell 主动发起，不是桌面应用内的自动 Agent。

## 12. 禁改项 / Forbidden Refactors

- 不把生成 provider、账号、额度或网络调用放入桌面运行时。
- 不把已搁置的点击目的地移动重新包装成 MVP 默认行为。
- 不用全局鼠标监听替代宠物窗口内点击和拖动。
- 不退化成平面动作 ID、固定时长轮播或随机硬切。
- 不把网关和交互节点加入随机睡姿池。
- 不让枕头在同一场景中无过渡出现、消失或改变尺度。
- 不用整个猫枕联合 alpha 作为宠物点击区域。
- 不用固定速度标量、CSS 内部平移或独立计时器代替逐帧 root motion。
- 不默认镜像正式左右素材。
- 不把动态 WebP 或 MP4 设为唯一运行时事实源。
- 不静默混入失败抠图帧、未批准候选或没有生产履历的素材。
- 不在运行时代码中写死某只宠物的十种姿势、猫窝或枕头拓扑。差异进入宠物包的图和行为配置，但不承诺任何两只宠物共享相同图。
- 不把验收串行片当作正式随机播放列表，也不从十个循环中直接随机硬切。
- 不把静态生图结果当作正式动作视频，或让静态 provider 直接写入可安装批准状态。
- 不为每只宠物各起一套渲染 Timer，也不因为共享渲染 Timer 就共享行为会话、随机状态或下一次换姿时间。
- 不把场景名称写死在 App 菜单或加载器白名单中。场景目录、中文名称和顺序来自宠物包，旧包兼容回退只用于迁移。
- 不把全局大小实现为逐帧素材重采样或动作重启。它只改变窗口显示尺寸，并保持当前 ground anchor、当前动作和各宠物固有相对体型。
- 不把 GitHub Windows Runner 通过写成 Windows 11 真实桌面通过，也不在未获授权时创建 Windows Release、MSIX 或签名产物。v0.6.0 的真机通过来自朋友明确反馈，不来自 CI 推断。
